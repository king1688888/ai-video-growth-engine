```text

先记录成本日志，再允许扣费；
先交接清楚，再进入下一个 Agent。
```

## 2. 文档目标

### 2.1 本文档要解决的问题

本项目是一个涉及视频处理、多模态理解、Content DNA、Creative IR、Prompt Registry、模型路由、异步任务、文件资产、积分计费、合规风控、人工复核、运营后台和发布监控的复合型 AI 商业产品。AIcoding 能大幅提升研发效率，但如果没有统一执行规约，会出现以下风险：

1. Agent 没有完整读取 D00 与专项文档，直接按经验写代码。
2. Agent 自行扩大 MVP1 范围，把对标账号抓取、完整视频生成、自动发布、团队协作等后置能力提前做进主流程。
3. Agent 把产品做成“复刻/搬运/洗稿/仿脸/仿声”工具，偏离项目定位。
4. Agent 只做前端页面和假数据，不做真实后端、数据库、任务队列、日志、计费和风控。
5. Agent 用 mock 冒充真实能力，未标记 Demo 模式，导致验收误判。
6. 多个 Agent 并行开发时，各自发明字段、API、状态枚举和错误码，造成集成失败。
7. Agent 修改数据库字段但不更新 D16，修改任务状态但不更新 D17，修改 Prompt 但不更新 D10/D12，修改计费但不更新 D19。
8. Agent 跳过测试、日志、异常处理、权限控制、成本记录和交接说明。
9. Agent 写死密钥、泄露测试数据、越权访问用户资产。
10. Agent 交付后没有启动命令、测试命令、回滚说明、风险说明和未完成项，导致后续 Agent 无法接手。

D23 必须把 AIcoding 研发从“自然语言派活”升级为：

```text
任务输入标准化
→ 文档读取强约束
→ 任务边界复述
→ 数据/API/Prompt/队列契约检查
→ 实施计划与变更清单
→ 分支与文件锁定
→ 工程实现
→ 自动化测试与人工验收
→ 风控/商业化/合规影响检查
→ PR / 交付说明 / 回滚说明
→ 文档回写 / 交接归档
```

D23 最终必须落到以下工程与管理对象：

1. `AgentTaskSpec`：标准任务输入结构。

10. 多 Agent 并行开发的文件锁、契约锁、冲突处理和升级机制。

## 4. 核心结论

1. **D23 是本项目 AIcoding 的“作业系统”**：所有 Agent 不再凭经验执行，而必须按统一输入、统一流程、统一输出、统一验收门禁执行。
2. **Agent 的第一职责不是写代码，而是守住边界**：先确认 D00、D03、D04、D05、D16、D17、D19、D21 是否允许做，再进入实现。
3. **任何任务都必须可追溯**：必须知道谁执行、读了哪些文档、改了哪些文件、影响哪些表/API/Prompt/队列/页面/积分/合规、跑了哪些测试、还有哪些风险。
4. **AI 能力必须工程化，不允许 Prompt Demo**：所有 AI 输出必须有 Prompt ID、版本、输入 Schema、输出 Schema、ModelCallLog、质量评测、失败回退和风控门禁。
5. **工程能力必须真实，不允许 UI Demo**：前端必须接 API，后端必须落库，长任务必须入队，成本必须记录，失败必须返还，风险必须可拦截。
6. **商业化必须贯穿任务链路**：高成本 AI 任务必须先报价、冻结积分、执行、记录成本、成功扣费或失败返还；不得后置补丁式计费。
7. **合规必须内建，不是上线前补免责声明**：授权确认、AIGC 标识、风险分级、拦截策略、人工复核、投诉删除必须进入主流程与测试门禁。
8. **多 Agent 并行必须先锁契约**：D16、D17、D10、D19、D21 涉及的硬契约变更必须走申请、审核、回写、测试，不能各自修改。
9. **交付不等于“我做完了”**：交付必须包含实现说明、文件清单、测试证据、启动命令、回滚说明、风险、未完成项、后续建议。
10. **D23 必须在研发早期执行**：它虽然编号靠后，但应在仓库初始化和第一批模块开发前就作为所有 Agent 的系统提示词和任务模板。

## 5. 详细设计

### 5.1 Agent 总角色定义

本项目所有 Agent 统一称为 AIcoding Agent。Agent 可以由 Manus、Codex、Claude Code、Hermes Agent、ChatGPT Project 或其他具备代码/文件/浏览器/终端能力的工具承担，但不因工具差异改变执行规则。

| Agent 类型 | 主要职责 | 必读文档 | 不得越界 |
|---|---|---|---|
| Orchestrator Agent / 总控 Agent | 拆任务、分配模块、检查依赖、合并交付、推进验收 | D00、D03、D04、D05、D20、D23、D24 | 不得绕过专项文档直接安排实现 |
| Product Agent | 将 PRD、页面、状态、验收标准转为研发任务卡 | D00、D03、D04、D05、D06、D23 | 不得新增 MVP1 外功能 |
| Frontend Agent | 实现页面、组件、状态、交互、API 联调、埋点 | D00、D04、D05、D06、D16、D17、D18、D19、D21、D23 | 不得用假数据冒充后端，不得隐藏错误或风控状态 |
| Backend Agent | 实现服务、API、数据库、鉴权、日志、幂等、计费联动 | D00、D04、D05、D15、D16、D17、D18、D19、D21、D23 | 不得擅自改字段/API/状态，不得跳过权限和审计 |
| AI / Prompt Agent | 实现 Prompt、Schema、模型调用、评测、失败回退 | D00、D07、D08、D09、D10、D11、D12、D13、D21、D23 | 不得写不可追踪 Prompt，不得生成复刻/仿脸/仿声指令 |
| Worker / Queue Agent | 实现视频处理、AI 长任务、导出、补偿、清理 | D00、D08、D10、D11、D16、D17、D19、D21、D23 | 不得把长任务放同步请求，不得跳过重试/死信/补偿 |

### 5.2 Agent 执行总流程

所有 Agent 必须按以下流程执行任务，不能跳步。

```text
1. 接收任务卡
2. 读取 D00
3. 读取任务直接相关专项文档
4. 复述任务目标、边界、不做事项
5. 检查依赖表、API、Prompt、队列、页面、权限、计费、合规
6. 判断是否需要 Contract Change Request
7. 输出实施计划与拟修改文件清单
8. 创建或确认 Git 分支
9. 实现代码 / 文档 / 配置
10. 添加或更新测试
11. 运行本地验证命令
12. 生成质量门禁报告
13. 更新 README / CHANGELOG / 迁移说明 / Prompt 版本说明
14. 输出交付说明、测试证据、风险和未完成项
15. 提交 PR 或交接给下一 Agent
16. 由 QA / Owner / 相关 Agent 验收
```

### 5.3 任务类型与执行粒度

| 任务类型 | 定义 | 示例 | 最小交付物 |
|---|---|---|---|
| `DOC_TASK` | 生成或更新产品/工程文档 | 更新 D16 API 字段 | Markdown、变更说明、影响文档 |
| `CONTRACT_TASK` | 数据库/API/队列/Prompt 契约变更 | 新增 `RiskAction` 枚举 | 迁移、Schema、API、测试、回写文档 |
| `FEATURE_TASK` | 新功能开发 | 视频上传与授权确认 | 代码、测试、日志、文档、交接 |
| `AI_TASK` | Prompt/模型/Schema/评测开发 | Content DNA 生成 Prompt | Prompt 模板、Schema、Benchmark、ModelCallLog |
| `QUEUE_TASK` | 异步任务/Worker/资产生命周期 | ASR/OCR 处理队列 | Worker、状态机、重试、死信、测试 |
| `BILLING_TASK` | 积分、订单、成本、扣费、返还 | 任务积分冻结 | 幂等服务、流水、成本日志、测试 |
| `COMPLIANCE_TASK` | 授权、审核、AIGC 标识、投诉删除 | 输入预检拦截 | 风控规则、审计、复核入口、测试 |
| `BUGFIX_TASK` | 修复缺陷 | 任务卡死不返还积分 | 根因、补丁、回归测试、事故记录 |
| `REFACTOR_TASK` | 不改变业务行为的重构 | 抽离 Model Adapter | 等价测试、无契约破坏证明 |
| `HOTFIX_TASK` | 生产紧急修复 | 积分重复扣除 | 最小补丁、回滚方案、事故复盘 |
| `RELEASE_TASK` | 发布、部署、监控、回滚 | MVP1 预发发布 | 发布记录、Smoke、监控、回滚点 |
| `HANDOFF_TASK` | 模块交接 | 后端 API 交接前端 | README、启动命令、测试命令、风险 |

### 5.4 Scope Gate：范围门禁

Agent 在执行前必须判断任务是否属于 MVP1。

#### 5.4.1 MVP1 允许范围

MVP1 允许实现：

1. 用户注册 / 登录。
2. 用户基础画像。
3. 视频上传与授权确认。
4. 文件安全校验、元数据解析、抽帧、ASR、OCR、镜头切分。
5. 多模态理解与 Content DNA。
6. 拆解报告、可复用/不可复用判断、风险提示。
7. Creative IR 与原创脚本生成。
8. 标题、封面建议、视频生成 Prompt。
9. 质检风控、相似度风险、合规拦截、人工复核入口。
10. 报告导出、生成历史、任务状态。
11. 模型调用日志、成本日志。
12. 基础积分、冻结、扣费、失败返还。
13. 后台任务查看、失败诊断、人工复核、投诉删除、补偿入口。
14. 测试、发布、监控、告警、交接。

#### 5.4.2 MVP1 禁止范围

Agent 不得在 MVP1 主流程中实现：

1. 全平台自动抓取。
2. 自动下载所有对标视频。
3. 自动发布。
4. 深度仿脸。
5. 深度仿声。
6. 明星/影视/综艺内容复刻。
7. 纯搬运号能力。
8. 复杂视频编辑器。
9. 移动端 App。
10. 一次性支持所有视频生成模型。
11. 大规模灰产爬虫。
12. 绕过平台限制的数据采集。
13. 高风险医疗、金融、法律结论性内容生成。
14. 未授权素材复用。
15. 平台规避检测能力。

#### 5.4.3 Scope Gate 决策

| 判断结果 | Agent 动作 |
|---|---|
| 明确属于 MVP1 P0 | 正常执行 |
| 属于 P1/P2 但文档允许预留 | 只做 Feature Flag、Schema 预留或后台禁用态，不进入主流程 |
| 超出 MVP1 且无明确授权 | 不执行，输出范围冲突说明 |
| 涉及禁止事项 | 拒绝实现，转 D21 合规复核 |
| 需求描述含糊 | 按 D00/D03/D04 最小边界执行，不自行扩展 |

### 5.5 Contract Gate：契约门禁

涉及以下内容时，Agent 必须先检查并必要时发起 Contract Change Request：

1. 数据库表、字段、索引、枚举、约束。
2. API 路径、请求体、响应体、错误码、鉴权、幂等键。
3. 任务状态、步骤状态、Job 状态、资产状态。
4. Prompt ID、变量、输出 JSON Schema、版本号。
5. 模型供应商、模型能力、成本字段、路由规则。
6. 积分冻结、扣费、返还、成本、毛利字段。
7. 风险等级、风控动作、人工复核状态。
8. 权限角色、数据分级、审计事件。
9. 页面 ViewModel 与前后端数据结构。
10. 测试门禁和发布门禁。

Contract Change Request 必须包含：变更原因、影响范围、兼容策略、迁移方案、回滚方案、测试计划、需要回写的文档。

### 5.6 Mock Policy：Mock 使用规则

Mock 只允许用于本地开发、前端联调、第三方供应商不可用时的隔离测试，不允许作为生产能力和验收依据。

| 场景 | 是否允许 Mock | 要求 |
|---|---:|---|
| 前端组件开发 | 允许 | Mock 数据必须放在 `fixtures/` 或 `mocks/`，页面显示 Demo 标识 |
| API 契约测试 | 允许 | 必须与 OpenAPI / D16 契约一致 |
| AI Prompt 调试 | 允许 | 必须保存 Mock 输出样本，不得写入生产结果表 |
| 模型供应商不可用 | 允许降级 | 必须记录 `provider_status=mock_or_stub`，不得扣真实积分 |
| 风控审核 | 仅测试允许 | 生产必须 Fail Closed，不允许 Mock 通过 |
| 计费扣费 | 不允许冒充真实 | 测试环境可用沙箱账户，必须区分 `test_mode` |
| 上线验收 | 不允许 | 验收报告必须基于真实链路或明确标注能力未完成 |

### 5.9 多 Agent 并行规范

多 Agent 并行必须遵守：

1. **模块隔离**：每个 Agent 只在自己模块目录内开发，跨模块改动必须申请。
2. **契约先行**：前后端并行前必须冻结 D16 API；Worker 并行前必须冻结 D17 状态；Prompt 并行前必须冻结 D10 Schema。
3. **文件锁**：同一文件同一时间只允许一个 Agent 主改，其他 Agent 只能评审或提出补丁。
4. **迁移锁**：数据库迁移由 Database/API Contract Agent 统一生成，其他 Agent 不得私自创建重复迁移。
5. **枚举锁**：状态枚举、错误码、风险等级、计费动作由契约 Agent 统一维护。
6. **PR 小粒度**：每个 PR 只解决一个任务或一组强相关改动，不得混合前端、后端、计费、风控大杂烩。
7. **集成窗口**：跨模块集成必须指定集成 Agent 和 QA Agent，不允许多个 Agent 同时改集成入口。
8. **冲突升级**：出现接口、字段、状态、Prompt、计费、合规冲突时，停止实现并提交冲突报告。

## 7. 异常与失败处理

### 7.1 文档缺失或读取失败

| 异常 | 处理策略 | 是否阻断 |
|---|---|---:|
| D00 缺失 | 停止任务，要求提供 D00 | 是 |
| D16/D17 等硬契约缺失 | 只能做文档草案或接口预留，不得写最终实现 | 是 |
| 专项文档缺失 | 按 D00/D04/D05 最小边界执行，并记录待确认 | 视任务而定 |
| 文档内容互相冲突 | 提交 `CONFLICT_REPORT`，按优先级处理 | 可能阻断 |
| 文档版本不明 | 记录读取时间和文件名，要求 Owner 确认 | 否，但需记录 |

### 7.2 范围异常

| 异常 | 处理策略 |
|---|---|
| 任务要求实现 MVP1 禁止事项 | 拒绝实现，输出合规与范围冲突说明 |
| 任务包含 P2/P3 后置能力 | 只做 Feature Flag 或 Schema 预留，不进入主流程 |
| 用户要求“尽量都做” | 按 D03/D04 收敛为 MVP1 P0 |
| Agent 发现实现成本过大 | 切分任务，不降低风控/计费/测试底线 |

### 7.3 契约异常

| 异常 | 处理策略 |
|---|---|
| 前端需要字段但 D16 无定义 | 创建 Contract Change Request，不得私自约定字段 |
| 后端返回结构与 D16 不一致 | 修正实现或回写 D16，必须补合约测试 |
| 任务状态与 D17 不一致 | 以 D17 为准，修正枚举和队列处理 |
| Prompt 输出 Schema 与 D10/D07/D09 冲突 | 修正 Prompt 或 Schema，跑 D12 回归 |
| 计费动作与 D19 冲突 | 以 D19 为准，补幂等和流水测试 |

### 7.4 实现异常

| 异常 | 处理策略 |
|---|---|
| 本地无法启动 | 不得交付为完成，必须提供失败日志和阻塞原因 |
| 测试失败 | 不得合并；若与环境有关，必须说明并提供复现方式 |
| 依赖安装失败 | 锁定版本或更换依赖，记录原因 |
| 数据库迁移失败 | 回滚迁移，修复脚本，补迁移测试 |
| 队列任务卡死 | 必须实现超时、重试、死信、补偿和状态修复 |
| 文件资产泄露风险 | 立即停止相关功能，转安全复核 |
| 积分重复扣费 | 立即热修，补偿用户，创建事故复盘 |

### 7.5 AI 能力异常

| 异常 | 处理策略 |
|---|---|
| 模型输出非 JSON | 执行 JSON repair；失败则降级或重试；不得保存无效结果 |
| Prompt 结果空泛 | 标记质量失败，进入 Prompt 回归与人工抽检 |
| 输出高相似 | 自动重写或拦截，必要时转人工复核 |
| 输出涉及仿脸/仿声/搬运 | 直接拦截，记录风险事件，不得导出 |
| 模型供应商超时 | 按 D11 降级或重试，记录 ModelCallLog，不得无限重试 |
| AI 风控不可用 | Fail Closed：不允许导出高风险输出 |

### 7.6 交付异常

| 异常 | 处理策略 |
|---|---|
| Agent 未提供测试证据 | 交付不通过 |
| Agent 未列修改文件 | 交付不通过 |
| Agent 未说明风险 | 要求补交风险说明 |
| Agent 修改了不相关文件 | 要求拆分 PR 或回滚无关改动 |
| Agent 未提供回滚说明 | 不得合并生产分支 |
| Agent 未更新相关文档 | 创建阻塞项，补回写后再验收 |

## 8. 风控与合规

### 8.1 Agent 级合规红线

所有 Agent 均不得实现、优化、包装、隐藏以下能力：

1. 搬运他人视频素材。
2. 1:1 克隆对标账号内容。
3. 洗稿式改写原文案。
4. 仿脸。
5. 仿声。
6. 明星、影视、综艺、名人内容复刻。
7. 绕过平台风控或规避检测。
8. 大规模未授权爬虫。
9. 未授权素材复用。
10. 高风险医疗疗效承诺、金融收益承诺、法律结论承诺。
11. 灰产引流、虚假宣传、诈骗诱导。
12. 删除或绕过 AIGC 标识、授权确认、审核与投诉删除机制。

### 8.2 风控嵌入研发流程

| 阶段 | 风控动作 |
|---|---|
| 任务输入 | 检查是否包含禁止能力或高风险意图 |
| 实施计划 | 标注风控影响和合规依赖文档 |
| 代码实现 | 接入授权、风险等级、审核、审计日志 |
| AI 输出 | 接入质量评分、相似度检查、合规拦截 |
| 导出前 | 必须检查 RiskCheckReport 和 AIGC 标识 |
| 交付前 | 提供风控测试或说明不涉及风控 |
| 上线前 | 按 D20/D21 合规门禁验收 |

### 8.3 AIGC 标识要求

涉及 AI 生成内容的 Agent 必须确保：

1. 页面展示 AI 生成提示。
2. 导出报告包含 AIGC 标识和用户使用责任提示。
3. 复制脚本/标题/Prompt 时保留必要提示。
4. 后台记录用户看到和确认标识的日志。
5. 若后续生成视频草稿，预留显式/隐式标识能力。

### 8.4 授权与投诉删除

Agent 实现上传、导出、后台、文件资产、人工复核、投诉处理时必须满足：

1. 上传前确认素材来源与授权。
2. 对标链接或视频仅用于结构学习和原创化重构，不输出复用素材指令。
3. 用户可发起投诉或删除申请。
4. 权利人投诉可暂停展示相关报告和派生资产。
5. 删除必须覆盖原始文件、抽帧、ASR/OCR、Content DNA、Creative IR、输出包、导出文件等派生资产。
6. 删除与复核操作必须写入审计日志。

### 8.5 安全与隐私

Agent 必须遵守：

## 9. 测试与验收标准

### 9.1 Agent 任务通用 DoD

任一 Agent 任务只有同时满足以下条件，才可标记为完成：

1. 已读取并列出 D00、D23 和任务相关专项文档。
2. 已复述任务边界和不做事项。
3. 未超出 MVP1 范围，或超出部分已 Feature Flag / 待确认。
4. 已实现真实逻辑，不是仅 UI Demo。
5. 涉及 mock 的地方已明确标记，生产默认关闭。
6. 涉及数据库/API/队列/Prompt/计费/合规变更已更新对应文档或创建回写任务。
7. 已添加或更新测试。
8. 已运行必要测试命令并提供结果。
9. 已记录日志、错误处理和异常状态。
10. 已提供启动命令、测试命令、回滚说明。
11. 已输出风险和未完成项。
12. 已提交交接说明。

### 9.2 测试分层要求

| 测试层级 | 适用任务 | 最低要求 |
|---|---|---|
| Lint / Typecheck | 所有代码任务 | 必须通过 |
| 单元测试 | Service、Utils、Prompt Parser、Billing Logic | 核心分支覆盖 |
| API 合约测试 | 后端 API | 请求/响应/错误码/权限/幂等 |
| 数据库迁移测试 | Schema 变更 | 迁移可执行、可回滚或有补偿 |
| 队列测试 | Worker/异步任务 | 成功、失败、重试、死信、补偿 |
| Prompt Schema 测试 | AI Prompt | JSON Schema 合法、字段完整 |
| AI Benchmark | AI 输出改动 | D12 样本集回归 |
| 风控红队测试 | 风控/生成/导出 | 高相似、仿脸仿声、未授权素材拦截 |
| 计费幂等测试 | 积分/订单/成本 | 重试不重复扣费，失败返还 |
| 权限安全测试 | 后台/文件/用户资产 | 越权访问被拒绝 |
| E2E 测试 | 主流程 | 上传→任务→报告→风控→扣费→导出 |
| Smoke 测试 | 发布任务 | 关键健康检查通过 |

### 9.3 任务验收矩阵

| 任务类型 | 必须通过的门禁 |
|---|---|
| 前端任务 | 页面状态、API 联调、权限状态、失败状态、E2E 或组件测试 |
| 后端任务 | 单元测试、API 合约测试、数据库测试、审计日志、错误处理 |
| AI/Prompt 任务 | Prompt 版本、Schema 校验、JSON repair、Benchmark、风控测试 |
| Worker 任务 | 队列状态、重试、死信、补偿、资产生命周期、日志 |
| Billing 任务 | 积分冻结、扣费、返还、幂等、成本日志、后台统计 |
| Compliance 任务 | 风险分级、拦截、人工复核、投诉删除、审计、测试 |
| DevOps 任务 | CI/CD、环境变量、监控、告警、回滚、Smoke |
| 文档任务 | 完整结构、可执行任务、提示词、Checklist、下载文件 |

### 9.4 不通过条件

出现任一情况，任务不得验收通过：

1. 未读取 D00。
2. 未说明任务边界。
3. 实现了禁止事项。
4. 只做 UI Demo 却声称完成。
5. 用 mock 冒充真实能力。
6. 数据库/API 与 D16 冲突。
7. 任务状态与 D17 冲突。
8. Prompt 改动无版本和 Benchmark。
9. 计费改动无幂等和返还测试。
10. 风控改动无拦截测试。
11. 未提供测试证据。
12. 未提供回滚说明。
13. 未输出风险和未完成项。
14. 泄露密钥或敏感数据。

D23 明确不做以下事项：

# 结语

D23 的最终目标不是让 Agent “更会写代码”，而是让 Agent 在复杂 AI 商业产品研发中始终遵守产品定位、MVP 边界、工程契约、商业化闭环、合规底线和验收标准。

从本文件生效开始，任何 AIcoding 任务都不应再以“我理解大概需求”为起点，而必须以“我已读取 D00、D23 和专项文档，并已确认范围、契约、测试和风险”为起点。只有这样，本项目才能避免从商业级 AI 产品退化为不可上线、不可计费、不可风控、不可交接的 Prompt Demo 或 UI Demo。

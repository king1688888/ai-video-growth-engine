## 2. 文档目标

### 2.1 本文档要解决的问题

D05 解决的是「如何把一个复杂 AI 产品拆成 AIcoding 可以稳定执行的工程模块」的问题，而不是重新定义产品战略或重复 D04 总 PRD。本文档必须解决以下问题：

1. **模块怎么拆**：把 MVP1 拆成可独立开发、测试、验收、交接的工程模块。
2. **模块边界在哪里**：明确每个模块负责什么、不负责什么、不能越界做什么。
3. **模块之间怎么通信**：只允许通过 API、数据库契约、事件、任务队列、对象存储引用和日志契约通信，不允许硬编码跨模块业务逻辑。
4. **模块输入输出是什么**：每个模块必须有输入、输出、状态、错误码、日志、权限和验收标准。
5. **AI 能力如何拆分**：把视频理解、Content DNA、Creative IR、Prompt 生成、质检风控等 AI 能力拆成独立任务，并定义 Schema、Prompt、评测、失败回退和质量标准。
6. **商业化如何不被遗漏**：积分预估、冻结、扣费、失败返还、成本记录、毛利统计必须作为独立模块且贯穿所有高成本任务。
7. **合规如何嵌入模块**：授权确认、AIGC 标识、风险分级、拦截策略、人工复核、投诉删除必须进入模块边界，而不是上线前临时补。
8. **AIcoding 如何并行执行**：每个模块都要给出 Agent 可直接复制执行的研发任务和提示词模板。
9. **如何验收模块完成**：定义模块级 DoD、集成级 DoD、上线级 DoD，避免“单模块说完成、整体不可用”。
10. **如何防止返工**：通过依赖顺序、契约冻结、Feature Flag、Scope Gate 和交接清单降低多 Agent 并行返工。

## 4. 核心结论

### 4.1 一句话结论

MVP1 必须被拆成“基础工程 + 用户画像 + 合规授权 + 视频资产 + 积分计费 + 异步任务 + 视频处理 + 多模态理解 + Content DNA + Creative IR + Prompt/模型调用 + 质检风控 + 报告导出 + 历史反馈 + 运营后台 + 监控测试”的独立模块，每个模块只能通过明确的数据、API、事件、任务队列和日志契约通信，禁止 Agent 跨模块硬编码和自行扩大范围。

### 4.2 模块拆分原则

1. **先契约，后实现**：先冻结模块输入输出、状态、错误码、日志、权限，再写业务实现。
2. **P0 先行，后置模块禁用**：MVP2-MVP4 只能保留字段、Feature Flag 和空状态，不允许进入默认主流程。
3. **AI 模块必须 Schema 化**：多模态理解、Content DNA、Creative IR、原创脚本、标题、封面、视频 Prompt、质检风控都必须有 JSON Schema、Prompt 版本、输出校验和失败回退。
4. **任务和计费必须绑定**：所有高成本任务必须先预估积分和冻结积分，成功后扣费，失败后返还，且记录模型成本。
5. **风控不可后置**：授权确认、意图预检、风险等级、拦截、人工复核、投诉删除必须进入主流程。
6. **不允许跨模块私有表写入**：除拥有模块外，其他模块只能通过公开 API、事件或服务方法访问数据。
7. **不允许 Mock 冒充真实能力**：开发阶段可使用 Mock，但必须有 `is_mock=true`、环境隔离、页面/后台标记和交接说明。
8. **每个模块必须有独立测试入口**：至少包含单元测试、API 测试、错误分支测试和最小集成测试。

## 5. 详细设计

## 5.1 模块边界总规则

### 5.1.1 模块间通信规则

允许的通信方式：同步 API、异步事件、任务队列、数据库引用 ID、对象存储引用、日志和审计事件、Feature Flag。禁止直接写其他模块私有表、前端持有永久对象存储凭证、Prompt 模块直接扣费、视频处理模块生成脚本、风控模块被前端绕过、后台无审计改积分、任务失败无日志无返还。

## 7. 异常与失败处理

## 7.1 全局失败处理原则

1. **失败必须可见**：用户看到失败原因和下一步建议，后台看到步骤、错误码、日志。
2. **失败必须可定位**：每个失败写入 `TaskStepLog`，AI 失败写入 `ModelCallLog`，计费失败写入 `CreditTransaction`。
3. **失败必须可补偿**：涉及积分冻结的任务必须释放、返还或部分结算。
4. **失败必须可重试**：可重试步骤必须有重试上限和幂等键。
5. **失败不能绕过风控**：风控失败默认保守，不直接放行高风险输出。
6. **失败不能吞掉成本**：模型调用失败或成功都要记录成本或失败原因。
7. **失败不能伪装成功**：部分成功必须标记 partial，不可展示为完整成功。

## 7.2 模块级失败矩阵

| 模块 | 失败场景 | 用户提示 | 系统处理 | 积分处理 |
|---|---|---|---|---|
| M01 | 登录失败 | 账号或验证码错误 | 记录 auth error | 不涉及 |
| M02 | 画像缺失 | 请先完成画像 | 阻止任务创建 | 不涉及 |

| M04 | 上传失败 | 上传失败，请重试 | 可重试 | 不冻结 |
| M04 | 格式不支持 | 当前格式不支持 | 拒绝资产 | 不冻结 |
| M05 | 余额不足 | 积分不足 | 阻止任务 | 不冻结 |
| M05 | 冻结失败 | 积分冻结失败 | 阻止任务 | 不执行 |

## 8. 风控与合规

## 8.1 合规底线

本项目所有模块必须遵守以下底线：不做搬运工具；不做克隆工具；不做洗稿工具；不做仿脸工具；不做仿声工具；不提供未授权素材复用能力；不提供绕过平台规则或平台风控的能力；不默认支持影视、综艺、明星娱乐内容复刻；不生成医疗疗效、金融收益、法律结论、招商收益等确定性高风险承诺；不以“爆款必成”“保证涨粉”“保证成交”等方式误导用户。

## 8.3 风险分级与动作

| 风险等级 | 示例 | 动作 |
|---|---|---|
| R0 | 用户要求参考结构做自己的原创脚本 | 放行 |
| R1 | 普通商业内容，轻微营销表达 | 放行 + 常规提示 |
| R2 | 标题轻度夸张、行业敏感但可改写 | 警告 + 重写建议 |
| R3 | 医疗/金融/法律/招商强承诺、疑似未授权素材 | 人工复核或限制输出 |
| R4 | 仿脸仿声、搬运、洗稿、绕过平台、违法违规 | 拦截 + 不生成 |

## 8.4 AIGC 标识策略

1. 报告和导出内容必须提示“本内容由 AI 辅助生成”。
2. 视频 Prompt 和脚本建议用户按目标平台规则添加 AIGC 标识。
3. 后续 MVP3 生成视频草稿时必须在导出页提供 AIGC 标识建议。
4. 用户下载报告时保留 AIGC 提示和免责声明。
5. 后台记录 AIGC 标识提示是否展示。

## 8.5 人工复核与投诉删除

人工复核触发条件：R3 风险、风险模型不确定且行业高风险、用户多次触发高风险意图、医疗/金融/法律/招商收益承诺、用户投诉侵权、输出相似度高但自动重写失败、用户要求恢复被拦截输出、后台运营手动标记异常。

投诉删除机制：用户或第三方提交投诉，记录 report_id、task_id、投诉原因、联系人和证据；后台将报告标记 under_review；高风险时临时隐藏相关输出；人工复核后决定删除、修改、保留或进一步沟通；删除必须记录 AuditLog；涉及积分补偿时走 M05/M13。

```text

```

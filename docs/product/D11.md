## 2. 文档目标

### 2.1 本文档要解决的问题

D11 解决的是 MVP1 中「模型怎么选、怎么调、怎么替换、怎么控成本、怎么失败回退、怎么和积分系统闭环」的问题。

本项目不是单模型 Demo，也不能把模型名称硬编码进 Prompt 或业务代码。MVP1 至少会涉及视频理解、帧描述、ASR 清洗、OCR 聚合、Content DNA、Creative IR、脚本生成、标题生成、封面建议、视频 Prompt 生成、质量评分、风险识别等多个 AI 调用点。不同调用点对模型能力、结构化输出、上下文长度、速度、价格、稳定性、合规策略和失败回退要求完全不同。如果不建立模型路由与成本控制层，项目会出现以下问题：

1. 模型散落在代码里，后续替换困难。
2. PromptRun 无法稳定记录模型版本、成本、延迟和失败原因。
3. 供应商超时或限流时任务卡死。
4. 高成本模型被免费用户大量调用，导致毛利失控。
5. 失败重试没有上限，成本不断扩大。
6. 价格变化无法及时同步，积分扣费与实际成本脱节。
7. 不同供应商返回格式不一致，Schema 校验和 JSON repair 失控。
8. 风险请求绕过路由，调用了不应开放的高能力模型。
9. 后台无法按用户、任务、模型、Prompt、功能统计成本和失败率。
10. AIcoding Agent 只接一个模型 API，做成不可商用的单点 Demo。

因此，D11 必须把模型调用从“直接请求某个供应商”升级为：

```text
PromptRun / AI Task
→ Model Router Quote
→ 成本预估与积分冻结
→ 模型能力匹配
→ 风险与权限门禁
→ 供应商健康检查
→ 路由决策
→ Provider Adapter 调用
→ 输出标准化
→ Schema 校验 / Repair / 质检 / 风控
→ ModelCallLog / CostLedger / CreditTransaction
→ 成功扣费或失败返还
→ 后台统计与告警
```

### 2.3 本文档的研发落点

D11 最终必须落到以下工程对象：

1. `ModelProvider`、`ModelCatalog`、`ModelCapability`、`ModelRoutePolicy`、`ModelRouteRule`、`ModelRouteDecision` 数据结构。
2. `ProviderAdapter` 标准接口与供应商适配器实现。
3. `ModelCallRequest`、`ModelCallResponse`、`ModelCallLog`、`CostEstimate`、`CostLedgerEntry`、`ProviderHealthCheck`、`ProviderQuotaUsage` 数据结构。
4. 模型路由服务：报价、路由、执行、重试、回退、熔断、日志、成本聚合。
5. 模型供应商配置后台：供应商、模型、能力、价格、配额、启停、健康状态、环境变量引用。
6. 成本控制后台：按用户、任务、Prompt、模型、供应商、日期、功能统计成本、毛利、失败率、重试成本。
7. 积分系统联动：预估、冻结、扣费、失败返还、部分成功结算、重复扣费防护。
8. 风控联动：高风险输入限制高能力模型、输出风险触发重写/降级/人工复核。
9. 测试体系：适配器契约测试、路由规则测试、成本计算测试、降级回退测试、计费幂等测试、供应商故障演练。
10. AIcoding 研发任务拆分与可复制执行提示词。

## 3. 与 D00 及其他文档的关系

| 当前优先 MVP1：视频拆解 + 原创脚本生成 | D11 P0 只覆盖视频理解、Content DNA、Creative IR、脚本/标题/封面/视频 Prompt、质量评分、风险识别，不把完整视频生成纳入默认主流程 |
| 不得自行扩大第一版范围 | 视频生成模型、批量账号抓取、自动发布、复杂编辑器仅做 P1/P2 预留和 Feature Flag，不进入 MVP1 默认路由 |

### 3.2 与 D10 的关系

D10 管理 Prompt 模板、变量、版本、PromptRun、输出 Schema 与回归测试。D11 不直接管理 Prompt 文本，而是接收 D10 生成的模型调用请求。

```text
D10 Prompt Registry
→ 渲染 Prompt
→ 创建 PromptRun
→ 传入 ModelRouteRequest
→ D11 选择模型并执行
→ 返回标准化 ModelCallResponse
→ D10 执行解析、Schema 校验、质量评分、风险检查
```

D10 必须向 D11 提供：

1. `prompt_run_id`。
2. `prompt_key`。
3. `prompt_version_id`。
4. 输入 Token / 多媒体规模估算。
5. 输出 Schema 严格程度。
6. 任务类型。
7. 质量模式。
8. 风险等级。
9. 用户套餐与权限。
10. 是否允许降级、是否允许替代模型。

D11 必须回写给 D10：

1. 实际供应商与模型。
2. 路由决策理由。
3. 请求与响应摘要。
4. 成本与延迟。
5. 重试和 fallback 记录。
6. 输出标准化结果。
7. 模型错误码。
8. 是否需要 JSON repair 或重跑。

### 3.3 与 D08 的关系

D08 负责视频处理与多模态证据包。D11 负责 D08 过程中可能发生的模型调用：

| D08 调用点 | D11 责任 |
|---|---|
| ASR / 音频转写 | 根据音频时长、语言、成本上限、用户套餐选择 ASR 服务或本地能力 |
| OCR / 字幕聚合 | 根据是否需要外部 OCR、输入图片数量、成本上限路由 |
| 关键帧描述 | 根据帧数量、视觉理解要求、输出 Schema 选择视觉模型 |
| 视频时间线理解 | 根据证据包规模、上下文长度和质量模式选择多模态模型 |
| 证据包修复 | 使用低成本结构化文本模型或 JSON repair 模型 |

### 3.4 与 D07/D09 的关系

D07/D09 定义 Content DNA 与 Creative IR。D11 按这些 Schema 的复杂度选择模型。

| 生成对象 | 路由原则 |
|---|---|
| Content DNA | 优先选择结构化输出强、长上下文稳定、多模态理解强的模型；失败后可降级为证据包摘要 + 文本模型生成 |
| 拆解报告 | 可选择文本结构化能力强、成本较低的模型；不必每次调用最贵模型 |
| Creative IR | 优先选择逻辑重构、原创化控制、风险约束理解强的模型 |
| 原创脚本 | 按质量模式和用户套餐选择高质量/标准/低成本文本模型 |
| 标题/封面建议 | 默认低成本模型，必要时批量生成后由质检模型筛选 |
| 视频 Prompt | 必须选择熟悉模型约束、结构化输出稳定的模型；不得直接复制原画面 |

### 3.5 与 D12/D21 的关系

D12/D21 负责质检、相似度风控、合规拦截。D11 必须在路由前后执行风控联动：

1. 输入风险为 R3/R4 时，不允许调用生成型高自由度模型直接产出脚本或视频 Prompt。
2. 高风险行业、疑似侵权、仿脸仿声、未授权素材请求必须先进入风险预检或人工复核。
3. 风控模型本身也走 D11，但必须使用隔离的 `risk_check` 任务类型和独立成本日志。
4. 输出被风控拦截时，D11 不得继续重试更高能力模型绕过拦截。
5. 投诉删除后，相关模型输入摘要、输出摘要和文件引用按 D22/D21 的留存策略处理。

### 3.6 与 D20 的关系

D20 负责商业化系统、套餐积分、订单与成本结算。D11 提供准确的成本估算和实际成本流水。

D11 必须向 D20 提供：

1. 任务预估成本。
2. 路由模型对应的预估积分。
3. 实际模型成本。
4. 重试成本。
5. fallback 成本。
6. 失败成本损失。
7. 部分成功成本。
8. 用户可见扣费建议。
9. 后台毛利统计基础数据。

## 4. 核心结论

### 4.1 一句话结论

D11 要建立一个独立的 `Model Router + Provider Adapter + Cost Ledger` 控制层，让所有模型调用都经过统一入口完成能力匹配、成本预估、权限风控、供应商适配、失败降级、日志审计和积分结算，禁止在业务代码、Prompt 模板或前端中直接硬编码模型供应商。

### 4.2 MVP1 P0 必须实现的范围

| 能力 | 是否 P0 | 说明 |
|---|---:|---|
| 模型供应商配置表 | 是 | 管理供应商、模型、能力、启停、密钥引用、环境、状态 |
| 模型能力矩阵 | 是 | 按文本、多模态、视觉、ASR、OCR、结构化输出、风控等能力建模 |
| 路由决策服务 | 是 | 根据任务类型、质量模式、成本上限、用户套餐、风险等级选择模型 |
| 成本预估服务 | 是 | 在任务前预估成本与积分冻结，不允许任务完成后才算账 |
| Provider Adapter 标准接口 | 是 | 标准化请求、响应、错误、重试、成本、日志 |
| ModelCallLog | 是 | 记录每次调用的模型、版本、成本、延迟、结果、错误、风险 |
| Retry / Fallback / Circuit Breaker | 是 | 供应商超时、限流、Schema 失败时可恢复，不让任务卡死 |
| 与积分系统集成 | 是 | 预估、冻结、成功扣费、失败返还、部分成功结算 |
| 后台成本与失败看板 | 是，轻量 | 按模型、供应商、任务、Prompt、用户统计成本和失败率 |
| 适配器契约测试 | 是 | 每个供应商接入前必须通过标准化测试 |

### 4.3 MVP1 不进入默认主流程的范围

1. 完整视频生成模型调用。
2. 分镜级视频片段生成。
3. 视频拼接与成片导出。
4. 自动发布模型或平台接口。
5. 多供应商自动竞价采购。
6. 根据实时价格自动改价。
7. 完整企业私有化模型网关。
8. 开放 API 给第三方调用模型路由。
9. 用户自带 API Key 计费模式。
10. 复杂 A/B 测试自动调参。

这些能力可以在数据表和 Feature Flag 中预留，但生产默认关闭。

### 4.4 路由原则

模型路由按以下优先级执行，不能只按“质量最高”或“价格最低”选择：

```text
合规允许
→ 用户权限允许
→ 任务能力匹配
→ 输出 Schema 能力匹配
→ 成本预算允许
→ 供应商健康可用
→ 历史质量评分达标
→ 延迟符合任务要求
→ 选择最优模型
→ 记录路由理由
```

### 4.5 成本控制原则

1. 任务创建前必须估算成本并冻结积分。
2. 每个模型调用必须记录实际成本、估算误差、重试成本和 fallback 成本。
3. 免费用户、试用用户、低价套餐必须有单任务成本上限和每日成本上限。
4. 高成本模型只允许付费套餐或后台白名单用户使用。
5. 重试必须有上限，且重试原因必须可审计。
6. JSON repair 优先使用低成本模型，不允许无脑重跑昂贵多模态模型。
7. 风控拦截后不得继续调用更高成本生成模型。
8. 供应商价格必须配置化，不允许硬编码在业务逻辑中。
9. 成本异常必须触发后台告警和自动熔断。
10. 用户可见积分扣费与后台实际成本要分层管理：积分是产品定价单位，模型成本是内部毛利核算单位。

## 5. 详细设计

### 5.1 模型路由在系统中的位置

D11 位于 D10 Prompt 运行服务与外部模型供应商之间，也服务于 D08、D07、D09、D12 的 AI 调用。

```text
业务任务 / PromptRun / 风控任务
→ ModelRouteRequest
→ Model Router
  → Policy Engine
  → Capability Matcher
  → Cost Estimator
  → Provider Health Checker
  → Risk & Permission Gate
→ ModelRouteDecision
→ Provider Adapter
→ Normalized ModelCallResponse
→ Schema 校验 / JSON repair / 质检 / 风控

```

### 5.5 路由策略

#### 5.5.1 规则路由优先

MVP1 路由默认采用规则引擎，不依赖 LLM 自行判断。原因：成本、权限、合规、模型健康状态必须确定可审计。

核心规则：

1. `task_type` 决定候选模型集合。
2. `required_capabilities` 过滤能力不匹配模型。
3. `risk_level` 过滤不允许处理高风险数据的模型。
4. `user_plan` 过滤套餐不可用模型。
5. `quality_mode` 决定高质量 / 标准 / 省钱优先。
6. `budget_cap` 过滤预估成本超限模型。
7. `provider_health` 过滤故障、熔断、禁用供应商。
8. `historical_quality_score` 低于阈值的模型不进入 P0 生产默认路由。
9. `latency_slo` 不满足时降低优先级或进入异步队列。
10. `schema_strictness` 高时优先选择结构化输出稳定模型。

#### 5.5.2 加权评分路由

候选模型通过过滤后，使用加权评分选择模型。

```text
route_score =
  quality_weight * normalized_quality_score
+ cost_weight * normalized_cost_score
+ latency_weight * normalized_latency_score
+ reliability_weight * provider_success_rate
+ schema_weight * schema_pass_rate
+ risk_weight * risk_safety_score
- fallback_penalty
- recent_error_penalty
```

MVP1 推荐默认权重：

| 场景 | 质量 | 成本 | 延迟 | 稳定 | Schema | 风控 |
|---|---:|---:|---:|---:|---:|---:|
| 视频理解 | 0.30 | 0.20 | 0.10 | 0.20 | 0.15 | 0.05 |
| Content DNA | 0.30 | 0.15 | 0.10 | 0.15 | 0.25 | 0.05 |
| Creative IR | 0.35 | 0.15 | 0.10 | 0.15 | 0.15 | 0.10 |
| 脚本生成 | 0.35 | 0.20 | 0.10 | 0.15 | 0.10 | 0.10 |
| 标题/封面建议 | 0.25 | 0.35 | 0.15 | 0.15 | 0.05 | 0.05 |
| 风控检查 | 0.20 | 0.15 | 0.10 | 0.20 | 0.20 | 0.15 |
| JSON repair | 0.10 | 0.45 | 0.20 | 0.15 | 0.10 | 0.00 |

#### 5.5.3 质量模式

| quality_mode | 适用用户 | 路由目标 |
|---|---|---|
| `economy` | 免费用户、轻量任务、JSON repair | 成本优先，质量达最低门槛 |
| `standard` | Starter 默认 | 质量与成本平衡 |
| `premium` | Pro / Team / Enterprise | 质量优先，仍受预算限制 |
| `safe_review` | 高风险任务、合规检查 | 风控和可解释性优先 |
| `benchmark` | D14 回归测试 | 固定模型或对照模型，保证可比性 |

### 5.7 成本估算与积分换算

#### 5.7.1 成本估算输入

| 输入 | 说明 |
|---|---|
| `task_type` | 影响候选模型和计费维度 |
| `input_token_estimate` | 文本输入 Token 估算 |
| `output_token_estimate` | 输出 Token 上限估算 |
| `media_seconds` | 音视频秒数 |
| `image_count` | 图片/关键帧数量 |
| `model_pricing_version` | 当前价格版本 |
| `retry_policy` | 最大重试次数 |
| `fallback_policy` | 可能 fallback 模型 |
| `quality_mode` | 影响模型选择和输出数量 |
| `deliverable_pack` | 输出包范围，例如基础版/标准版/高级版 |

#### 5.7.2 成本估算公式

```text
estimated_model_cost =
  input_tokens * input_token_unit_price
+ output_tokens * output_token_unit_price
+ media_seconds * media_second_unit_price
+ image_count * image_unit_price
+ fixed_request_fee
```

加入风险系数：

```text
estimated_task_cost =
  sum(estimated_model_cost_per_step)
  * retry_buffer_factor
  * fallback_buffer_factor
  * exchange_rate_buffer
```

积分预估：

```text
estimated_credits = ceil(
  estimated_task_cost
  * internal_fx_rate
  * gross_margin_multiplier
  / credit_unit_value
)
```

说明：

1. `credit_unit_value`、`gross_margin_multiplier`、套餐折扣由 D20 最终定义。
2. D11 只计算模型成本和建议积分，不定义最终售卖价格。
3. 实际扣费可按产品输出包固定扣费，而不是完全按模型成本浮动。
4. 如果实际成本高于预估但未超过系统容忍阈值，不向用户追加扣费；后台记录毛利损失。
5. 如果实际成本显著高于预估，触发成本异常告警并冻结相关路由策略。

#### 5.7.3 积分冻结与结算

```text
用户创建任务
→ D11 生成 CostEstimate
→ D20 创建 CreditReservation
→ D11 执行模型调用
→ 每次调用写 CostLedgerEntry
→ 任务成功：D20 将 reservation 转为 CreditTransaction charged
→ 任务失败：按失败阶段和可用产出返还积分
→ 部分成功：只扣已交付价值对应积分，其余释放或返还
```

### 5.8 重试、降级与熔断

#### 5.8.1 重试规则

| 错误类型 | 是否重试 | 最大重试 | 是否换模型 | 用户可见 |
|---|---:|---:|---:|---|
| 网络短暂失败 | 是 | 2 | 否 | 否，仅进度显示处理中 |
| 供应商 5xx | 是 | 2 | 可 | 否 |
| 限流 / 配额不足 | 是 | 1 | 是 | 否或提示排队 |
| 超时 | 是 | 1-2 | 是 | 可能提示处理中延迟 |
| JSON 解析失败 | 是 | 2 | 优先 JSON repair | 否 |
| Schema 校验失败 | 是 | 2 | 可换模型 | 否 |
| 安全拒绝 | 否 | 0 | 否 | 是，显示合规原因 |
| 风控拦截 | 否 | 0 | 否 | 是，给原创化建议或人工复核入口 |
| 余额不足 | 否 | 0 | 否 | 是 |
| 任务取消 | 否 | 0 | 否 | 是 |

#### 5.8.2 降级策略

| 原任务 | 降级方案 | 用户价值 |
|---|---|---|
| 视频理解失败 | 用 ASR/OCR/关键帧摘要生成低置信度 Content DNA | 可输出基础报告，标记低置信度 |
| Content DNA 失败 | 使用备用 Prompt + 低成本结构化模型修复 | 保留核心拆解能力 |
| Creative IR 失败 | 输出拆解报告，不生成脚本，返还原创输出部分积分 | 保证已完成价值可见 |
| 标题/封面失败 | 延后异步补生成或使用备用模型 | 不阻塞报告主流程 |
| 视频 Prompt 失败 | 输出脚本和标题，返还视频 Prompt 部分积分 | 降低失败损失 |
| 风控模型不可用 | 保守阻断高风险输出，低风险任务进入人工抽检或降级 | 合规优先 |
| 供应商大面积故障 | 熔断供应商，转备用供应商或排队 | 避免任务卡死 |

#### 5.8.3 熔断规则

供应商或模型满足以下任一条件时自动进入 `degraded` 或 `disabled`：

1. 最近 10 分钟错误率超过阈值。
2. 最近 10 分钟超时率超过阈值。
3. 成本异常超过预估 2 倍且连续出现。
4. Schema 失败率显著高于基线。
5. 安全拒绝率异常升高。
6. 供应商密钥失效。
7. 后台手动禁用。

熔断后：

1. 新任务不再路由到该模型。
2. 已在执行任务按任务级 fallback 策略处理。
3. 后台触发告警。
4. 恢复必须通过健康检查和少量探测任务。

## 7. 异常与失败处理

### 7.1 路由异常

| 异常 | 触发条件 | 处理策略 | 用户可见提示 | 是否返还积分 |
|---|---|---|---|---|
| 无可用模型 | 候选模型均被禁用、不可用或不满足能力 | 任务不执行，提示系统繁忙或转人工 | 是 | 释放冻结积分 |
| 套餐权限不足 | 用户套餐不允许当前模型/质量模式 | 提示升级或切换标准模式 | 是 | 不冻结或释放 |
| 成本超限 | 预估成本超过任务/用户/套餐上限 | 降级质量模式或提示升级 | 是 | 不冻结或释放 |
| 风险门禁失败 | R3/R4 请求不允许自动生成 | 阻断或转人工复核 | 是 | 释放未消耗积分 |
| 价格配置缺失 | 无有效 pricing_version | 禁用该模型，fallback | 否，后台告警 | 视执行情况 |
| 供应商健康异常 | outage/disabled/degraded | fallback 或排队 | 可提示排队 | 不因未执行扣费 |

### 7.2 调用异常

| 异常 | 处理策略 | 最大重试 | 成本处理 |
|---|---|---:|---|
| 网络错误 | 同模型重试 | 2 | 失败不向用户扣未交付积分，后台记录损耗 |
| 供应商超时 | 同模型重试一次后 fallback | 2 | 记录超时成本，超过阈值告警 |
| 限流 | fallback 或排队 | 1 | 不重复扣费 |
| Provider 5xx | fallback | 2 | 记录供应商异常 |
| Provider 4xx 参数错误 | 不重试，标记适配器错误 | 0 | 平台承担，不向用户扣对应失败部分 |
| 输出为空 | 重试或 fallback | 1 | 失败返还对应部分 |
| JSON 解析失败 | JSON repair，仍失败则 fallback | 2 | repair 成本进入后台成本，用户按交付结果扣费 |
| Schema 校验失败 | repair 或重跑 | 2 | 多次失败转人工或返还 |
| 安全拒绝 | 不换模型绕过，转风控处理 | 0 | 返还未交付部分 |
| 内容风险升高 | 停止后续生成，创建复核单 | 0 | 按已交付低风险内容结算或返还 |

### 7.3 计费异常

| 异常 | 处理策略 |
|---|---|
| 预估积分过低 | 后台记录预估误差；用户不追加扣费；必要时调整路由策略和输出包价格 |
| 实际成本高于阈值 | 告警 + 冻结模型策略 + 人工复核价格配置 |
| 重试导致重复扣费 | 使用 `idempotency_key`、`credit_reservation_id`、`model_call_id` 防重 |
| fallback 成功但成本高于原模型 | 按用户已确认输出包扣费，后台统计毛利损失 |
| 任务失败但模型已消耗 | 用户按失败规则返还，平台吸收失败成本或按 D20 策略结算 |
| 部分成功 | 只对可见交付物扣费，失败交付物返还 |
| 用户取消 | 停止未执行队列；已完成且可交付部分按规则结算 |

### 7.4 供应商配置异常

| 异常 | 处理策略 |
|---|---|
| API Key 失效 | 自动禁用供应商，告警 DevOps，fallback |
| 密钥泄露风险 | 立即禁用密钥，轮换 Secret，审计调用日志 |
| 供应商返回结构变更 | 适配器测试失败，禁用模型，回滚 adapter_version |
| 价格配置过期 | 后台提醒更新；过期后禁止高成本模型生产使用 |
| 模型下线 | 标记 deprecated，路由迁移到替代模型，回写 D11/D16 |

## 8. 风控与合规

### 8.1 基础原则

1. D11 不负责判断最终法律结论，但必须执行 D12/D21 的风险门禁。
2. 模型路由不得绕过授权确认、AIGC 标识、风险分级、人工复核和投诉删除流程。
3. 高风险输入不得直接进入高自由度生成模型。
4. 供应商适配必须记录数据处理边界，包括是否允许处理用户上传视频、是否允许企业数据、是否需要本地/私有化能力。
5. 所有模型输出必须标记 AIGC 辅助生成，最终由 D06/D21 在前端展示。
6. 用户投诉、删除、侵权申诉触发后，关联 `model_call_logs`、`prompt_runs`、`prompt_assets`、`generated_outputs` 必须进入冻结或删除流程。

### 8.2 风险等级与路由动作

| 风险等级 | 含义 | D11 路由动作 |
|---|---|---|
| R0 | 正常低风险 | 正常路由 |
| R1 | 轻微风险，如行业承诺需谨慎 | 路由到标准模型，后置质检 |
| R2 | 中风险，如强营销、疑似夸大 | 使用 safe_review 模式，生成后必须质检 |
| R3 | 高风险，如疑似仿脸仿声、未授权素材、强相似复制 | 阻断生成模型，只允许解释性拆解或转人工复核 |
| R4 | 禁止风险，如绕过平台、复制搬运、违法违规 | 直接拦截，不调用生成模型，记录审计 |

### 8.3 授权与 AIGC 标识

D11 必须读取以下上下文：

1. `authorization_confirmed`：用户是否确认素材来源和使用边界。
2. `aigc_label_required`：是否必须在输出中显示 AIGC 辅助生成标识。
3. `blocked_capabilities`：本任务禁用能力列表。
4. `risk_level`：风险等级。
5. `manual_review_required`：是否必须人工复核。

未确认授权时：

1. 不允许执行视频理解、Content DNA、Creative IR 或脚本生成。
2. 可返回前端要求用户确认授权。
3. 不冻结积分，或释放已冻结积分。

### 8.4 人工复核与投诉删除

触发人工复核的情况：

1. R3 风险。
2. 模型安全拒绝。
3. 输出疑似高度相似。
4. 用户投诉侵权。
5. 供应商异常导致输出不可解释。
6. 成本异常且影响用户扣费。

投诉删除处理：

1. 冻结相关用户可见输出。
2. 标记关联 `ModelCallLog` 为 `complaint_pending`。
3. 删除或隔离输出资产，按 D22 数据生命周期执行。
4. 保留必要审计哈希与操作日志。
5. 后台生成客服处理记录和补偿建议。

### 8.5 数据安全

1. 供应商密钥使用 Secret Manager，不进入数据库或日志。
2. 模型输入输出日志默认脱敏存储。
3. 用户上传视频、音频、帧图只传递必要引用，不在调试日志中展开。
4. 企业用户或高隐私任务可配置仅使用指定供应商或本地模型。
5. 后台查看完整输入输出必须有 RBAC 权限和审计日志。
6. 开发环境 Mock 数据不得使用真实用户隐私素材。

## 15. 结论

D11 是本项目从“能调模型”走向“能商业化运营模型”的关键控制层。MVP1 不需要一次性接入所有模型，也不需要追求最复杂的智能路由；真正必须优先完成的是统一模型入口、供应商适配契约、成本估算、积分冻结、失败返还、模型调用日志、fallback、熔断、后台成本统计和风控门禁。

只要模型调用还散落在业务代码里、价格还硬编码、失败还无限重试、成本还不可追踪、积分还不能补偿、Mock 还可能混入生产，本项目就不能进入商业级上线。D11 完成后，D12 风控、D14 Benchmark、D16/D17 工程契约、D20 商业化和 D23 运营后台才能稳定承接真实用户、真实任务、真实成本和真实补偿。

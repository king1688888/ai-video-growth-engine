## 2. 文档目标

### 2.1 本文档要解决的问题

D01 不是泛泛而谈的创业分析，也不是融资 BP。本文件要把「AI 自媒体产品到底是什么、为什么用户付费、第一版怎么形成闭环、哪些事情坚决不做、AIcoding 怎么落地」固化成可执行的产品与工程约束。

D01 必须解决以下问题：

1. 产品到底应该被定义成什么。
2. 产品不能被定义成什么。
3. MVP1 为什么先做「视频拆解 + 原创脚本生成」。
4. 用户为什么愿意付费。
5. 第一个 Aha Moment 如何在产品里被工程化。
6. 商业闭环如何与任务、积分、模型成本、后台统计打通。
7. 合规底线如何嵌入产品表达、输入校验、风控、人工复核和投诉删除。
8. AI 能力如何以 Schema、Prompt、评测、失败回退和质量标准进入研发。
9. 工程实现需要预留哪些数据库、API、任务队列、日志、权限、测试和部署影响。
10. AIcoding Agent 应该如何按任务拆分执行，避免做成 UI Demo 或 Prompt Demo。

## 4. 核心结论

### 4.1 产品战略定位

推荐统一产品定位：

> 面向短视频创作者、企业 IP、本地商家、内容团队和 MCN 的 AI 短视频爆款增长引擎。用户输入对标账号、爆款视频、账号 ID、作品列表或自有作品数据后，系统通过多模态理解模型拆解爆款规律，提炼 Content DNA，经过 Creative IR 原创化重构，生成适合用户行业、人设、产品和素材的原创脚本、分镜、标题、封面建议、视频生成 Prompt 和视频草稿，并根据发布数据持续诊断、归因、优化和进化。

### 4.2 第一版产品形态

MVP1 只做：

> AI 爆款视频拆解与原创脚本生成工具。

MVP1 的核心交付物：

1. 视频拆解报告。
2. Content DNA 摘要。
3. 可复用结构清单。
4. 不可复用风险清单。
5. 原创脚本 5 条。
6. 标题 10 条。
7. 封面建议 3 条。
8. 视频生成 Prompt 3 条。
9. 风控提示与原创化建议。
10. 可导出的报告文件。
11. 生成历史、任务状态、积分扣费、模型成本与后台日志。

### 4.3 产品商业本质

产品商业本质不是调用模型生成一段文案，而是：

> 将短视频内容生产中高度依赖经验的「拆爆款、找结构、改脚本、出选题、做分镜、生成 Prompt、复盘数据」流程，转化为可产品化、可复用、可计费、可持续进化的 AI 工作流。

### 4.4 首发商业闭环

MVP1 首发商业闭环为：

```text
用户上传一条对标视频
→ 确认授权与使用边界
→ 系统预估积分并冻结
→ 视频处理与多模态拆解
→ 输出 Content DNA 与拆解报告
→ 输出原创脚本 / 标题 / 封面建议 / 视频 Prompt
→ 风控与相似度检查
→ 成功后扣费并开放导出
→ 失败则按规则返还积分
→ 后台记录任务、成本、质量、风险和转化事件
→ 用户二次上传或购买套餐
```

### 4.5 最重要的产品取舍

| 方向 | 决策 |
|---|---|
| 是否做对标账号 1:1 复制 | 不做 |
| 是否做搬运/下载/批量抓取 | 不做 |
| 是否做仿脸/仿声 | 不做 |
| 是否第一版做完整视频生成 | 不做，MVP3 再做 |
| 是否第一版做全平台账号自动采集 | 不做，MVP2 后再做手动或授权导入 |
| 是否第一版做自动发布 | 不做 |
| 是否第一版做数据诊断 | 仅预留字段，MVP4 再做 |
| 是否第一版做积分扣费 | 必须做基础版 |
| 是否第一版做后台任务/成本查看 | 必须做轻量版 |
| 是否第一版做风控合规 | 必须做基础版，不可后置 |

### 4.6 长期壁垒

长期壁垒不是模型 API，而是：

1. 行业 Content DNA 数据库。
2. 用户专属 Prompt 资产。
3. 行业高表现模板库。
4. 用户发布数据与归因结果。
5. 原创化重构规则。
6. 相似度风控与合规规则。
7. 多模型路由与成本控制系统。
8. AI Benchmark 与回归测试集。
9. 创作者工作流与团队协作体系。
10. 企业级运营后台与人工复核能力。

## 5. 详细设计

## 5.1 产品定位设计

### 5.1.1 推荐产品名称方向

| 名称方向 | 适合程度 | 说明 |
|---|---:|---|
| AI 短视频爆款增长引擎 | 高 | 最准确，适合正式文档与产品定位 |
| 爆款 DNA | 高 | 适合品牌名，强调内容结构资产 |
| 内容 DNA 引擎 | 高 | 偏技术与产品能力 |
| AI 爆款导演 | 中高 | 适合后续视频生成阶段 |
| 对标增长引擎 | 中 | 容易被误解为复刻，需要配合合规表达 |
| 短视频增长 Copilot | 中 | 偏通用，但安全 |
| 账号复刻工具 | 禁用 | 高风险，偏搬运和克隆 |
| 爆款复制器 | 禁用 | 高风险，平台与版权风险高 |

### 5.1.2 标准对外表达

推荐表达：

> 输入同行爆款视频或对标账号，系统自动拆解爆款结构，提炼 Content DNA，并生成适合你账号、行业、人设和产品的原创脚本、分镜、标题、封面建议和视频生成 Prompt。

可用于官网首屏的安全表达：

> 不是搬运爆款，而是把爆款的底层结构变成你的原创内容生产力。

可用于产品内引导：

> 我们只学习内容结构、钩子逻辑、节奏与转化路径，不复用原视频素材、台词、人物、声音、配乐、商标或封面设计。

### 5.1.3 禁用表达

以下表达在官网、产品页、按钮、Prompt、客服话术、AI 输出中禁用：

1. 1:1 复刻对标账号。
2. 原样复制爆款视频。
3. 自动搬运视频。
4. 克隆任意账号。
5. 洗稿神器。
6. 仿某某声音。
7. 仿某某人脸。
8. 绕过平台审核。
9. 平台搬运不降权。
10. 自动下载对标账号全部作品。
11. 未授权素材复用。
12. 爆款视频秒变你的同款。

### 5.1.4 用户价值主张

| 用户类型 | 价值主张 |
|---|---|
| 企业 IP / 老板 IP | 快速把同行爆款结构转成自己的观点、案例和转化型口播脚本 |
| 本地生活商家 | 把同城同行的爆款内容结构迁移成门店活动、案例、探店和老板 IP 内容 |
| 知识 IP / 教培 | 从高表现内容里提炼钩子和信息结构，生成系列化干货脚本 |
| 内容团队 / MCN | 降低人工拆解成本，批量沉淀模板，提高脚本产出效率 |
| 代运营公司 | 把“人工经验服务”产品化成可复制的客户交付 SOP |

## 5.2 首发目标用户与商业场景

### 5.2.1 首发用户优先级

| 优先级 | 用户类型 | 为什么优先 | MVP1 核心交付 |
|---|---|---|---|
| P0 | 企业 IP / 老板 IP | 付费能力强，内容需求持续，合规风险相对可控 | 口播脚本、观点重构、转化型内容 |
| P0 | 本地生活商家 | 对标需求强，行业可模板化，商业转化明确 | 同行爆款拆解、活动脚本、门店案例内容 |
| P1 | 知识 IP / 教培 | 脚本价值高，选题和钩子需求强 | 干货脚本、标题封面、系列选题 |
| P1 | MCN / 内容工作室 | 批量需求强，客单价高，但流程复杂 | 多账号批量拆解、团队模板库 |
| P2 | 电商带货 / 招商加盟 | 有转化价值，但风控和夸大宣传风险更高 | 种草脚本、转化 CTA、风险提示 |

### 5.2.2 MVP1 的用户作业场景

MVP1 不追求覆盖所有自媒体工作流，只解决最强痛点：

```text
用户看到一条同行爆款
→ 不知道为什么爆
→ 不知道怎么改成自己的内容
→ 不知道能学什么、不能学什么
→ 不知道怎么生成可拍摄脚本和视频 Prompt
→ 用本产品得到拆解报告、原创脚本和 Prompt
→ 节省拆解时间并提升脚本质量
```

### 5.2.3 第一 Aha Moment

第一 Aha Moment 必须被产品和工程明确承接：

> 用户上传一条同行爆款视频后，系统在可接受时间内输出一份清晰拆解报告，并生成 5 条适配用户行业、人设和产品的原创脚本，让用户感觉“这不是泛泛改写，而是真的把爆款结构变成了我的内容”。

Aha Moment 触发条件：

| 触发项 | 标准 |
|---|---|
| 用户输入完整 | 至少有视频文件/链接、行业、目标平台、人设/产品简述、授权确认 |
| 报告可理解 | 报告包含钩子、结构、情绪曲线、转化路径、可复用/不可复用 |
| 输出可行动 | 至少 3 条脚本可直接拍摄或交给团队改稿 |
| 风险可感知 | 明确告诉用户哪些不能复制以及为什么要原创化 |
| 导出可用 | 用户可复制、下载或导出报告 |
| 成本透明 | 用户知道扣了多少积分、失败是否返还 |

## 5.3 MVP1 产品边界

### 5.3.1 MVP1 必须做

| 模块 | 是否 P0 | MVP1 要求 |
|---|---:|---|
| 登录注册 | 是 | 支持基础用户身份与任务归属 |
| 用户画像 | 是 | 至少采集行业、平台、人设、产品/服务、目标用户、内容目标、禁用内容 |
| 视频上传 | 是 | 支持常见视频格式，限制大小/时长，必须有授权确认 |
| 视频处理 | 是 | 元数据解析、抽帧、ASR、OCR、镜头切分可逐步增强 |
| 多模态理解 | 是 | 输出结构化视频理解结果 |
| Content DNA | 是 | 输出钩子、结构、情绪曲线、转化路径、可复用/不可复用 |
| 原创脚本生成 | 是 | 至少 5 条，且明显区别于原视频 |
| 标题生成 | 是 | 至少 10 条，避免标题党和虚假承诺 |
| 封面建议 | 是 | 至少 3 条，含文案与构图，不复刻原封面 |
| 视频生成 Prompt | 是 | 至少 3 条，可复制到外部视频模型 |
| 质检风控 | 是 | 基础质量评分、相似度风险、合规风险提示 |
| 任务状态 | 是 | queued/processing/.../completed/failed/cancelled |
| 积分扣费 | 是 | 预估、冻结、成功扣除、失败返还 |
| 模型成本记录 | 是 | 记录供应商、模型、token/媒体量、成本、延迟、状态 |
| 后台任务查看 | 是 | 轻量查看任务、用户、成本、风险、失败 |
| 报告导出 | 是 | 支持 Markdown/PDF/HTML 之一，MVP1 优先 Markdown 或 PDF |

### 5.3.2 MVP1 坚决不做

1. 不做全平台自动抓取。
2. 不做自动下载对标账号全部作品。
3. 不做自动发布。
4. 不做深度仿脸。
5. 不做深度仿声。

### 5.4.3 商业化模型

MVP1 建议支持 4 类计费方式：

| 模式 | MVP1 是否支持 | 说明 |
|---|---:|---|
| 免费额度 | 支持 | 新用户 1 次轻量拆解或部分输出，用于触发 Aha Moment |
| 按次付费 | 支持 | 单条深度拆解、单次脚本包、单次导出 |

### 5.4.4 积分扣费原则

积分必须与任务状态和模型成本绑定，不允许任务创建后直接不可逆扣费。

标准流程：

```text
用户发起任务
→ 系统预估积分
→ 检查余额 / 套餐额度
→ 冻结积分
→ 执行任务
→ 成功后正式扣除
→ 失败后按规则返还
→ 记录 CreditTransaction
→ 记录 ModelCallLog
→ 后台统计毛利
```

### 5.4.5 MVP1 积分消耗建议

> 以下为产品策略建议，最终价格由 D20 商业化系统文档确认。

| 任务类型 | 免费用户 | 付费用户 | 预估积分 | 扣费时机 |
|---|---:|---:|---:|---|
| 轻量视频拆解 | 1 次 | 可用 | 10-20 | 成功输出轻量报告后 |
| 深度视频拆解报告 | 限制预览 | 可用 | 30-60 | 完成报告后 |
| 原创脚本 5 条 | 不完整开放 | 可用 | 20-40 | 脚本生成成功后 |
| 标题 10 条 | 可部分开放 | 可用 | 5-10 | 生成成功后 |
| 封面建议 3 条 | 可部分开放 | 可用 | 5-10 | 生成成功后 |
| 视频 Prompt 3 条 | 限制预览 | 可用 | 10-30 | Prompt 生成成功后 |
| 报告导出 | 限制 | 可用 | 5-15 | 导出成功后 |
| 风控检查 | 内置 | 内置 | 不单独计费 | 计入任务成本 |
| 失败重试 | 系统承担上限内 | 系统承担上限内 | 不重复扣用户积分 | 记录失败成本 |

### 5.4.6 失败返还原则

| 场景 | 扣费策略 | 返还策略 | 记录要求 |
|---|---|---|---|
| 文件上传失败 | 不冻结或自动释放 | 全额返还 | UploadErrorLog |
| 用户未确认授权 | 不创建付费任务 | 不扣费 | ComplianceAckLog |
| 视频解析失败 | 若未调用高成本模型，全额返还 | 全额或部分返还 | VideoProcessingJob + CreditTransaction |
| ASR/OCR 部分失败 | 若仍可输出降级报告，可部分扣费 | 按质量等级部分返还 | QualityCheckReport |
| 多模态模型失败 | 重试上限内不重复扣用户积分 | 失败后返还未实际消耗部分 | ModelCallLog |
| Prompt 生成失败 | 重试后仍失败则返还该步骤积分 | 该步骤返还 | PromptRunLog |
| 风控极高风险拦截 | 若未生成主要交付物，返还大部分积分 | 可保留基础检测成本 | RiskCheckReport + CreditTransaction |
| 用户主动取消 | 按已执行阶段结算 | 未消耗部分返还 | AuditLog |
| 系统超时 | 若无可用输出，返还主要积分 | 根据成本与输出补偿 | TaskLog + CreditTransaction |

## 6.7 Prompt 设计

> D01 不替代 D10，但必须给出与产品战略、商业闭环和风控相关的 Prompt 原型，确保 AIcoding 可实现最小策略判断与质量检查。

### 6.7.1 Prompt A：用户意图与风险分类 Prompt

#### 使用场景

用户创建任务前，系统根据用户输入判断其意图是否符合产品定位，是否存在搬运、克隆、仿脸、仿声、未授权素材复用等风险。

#### 输入 Schema

```json
{
  "user_profile": {
    "industry": "string",
    "persona": "string",
    "product_or_service": "string",
    "target_audience": "string",
    "content_goal": "string"
  },
  "task_request": {
    "source_type": "uploaded_video|video_link|account_link",
    "user_instruction": "string",
    "originality_level": "low_reference|medium_rewrite|high_reconstruction|strong_original_series",
    "target_platform": "string"
  },
  "compliance_ack": {
    "authorization_ack": true,
    "ack_version": "string"
  }
}
```

#### 输出 Schema

```json
{
  "intent_type": "structure_learning|original_generation|high_similarity_copy|face_clone|voice_clone|platform_evasion|unknown",
  "allowed": true,
  "risk_level": "low|medium|high|critical",
  "risk_reasons": ["string"],
  "required_action": "allow|warn|force_rewrite|block|manual_review",
  "recommended_originality_level": "medium_rewrite|high_reconstruction|strong_original_series",
  "safe_user_message": "string",
  "internal_notes": "string"
}
```

#### Prompt 模板

```text
你是 AI 短视频爆款增长引擎的产品风控与意图分类 Agent。
你的任务不是帮助用户复刻、搬运、洗稿、仿脸、仿声，而是判断用户请求是否符合“结构学习 + 原创化生成”的产品定位。

请根据输入的 user_profile、task_request、compliance_ack 判断：
1. 用户意图属于结构学习、原创生成，还是高相似复制、仿脸、仿声、平台规避等高风险意图。
2. 是否允许进入任务。
3. 风险等级。
4. 系统应采取的动作：allow、warn、force_rewrite、block、manual_review。
5. 给用户的安全提示语。

必须只输出 JSON，不要输出解释性长文。
如果用户要求“照着一模一样做”“复刻同款”“仿这个人的脸/声音”“绕过平台检测”“搬运不降权”，必须判定 high 或 critical。
如果用户只是学习结构、钩子、节奏、转化路径，并明确要求原创化，允许进入任务。
```

#### 质量标准

| 指标 | 标准 |
|---|---|
| 结构化输出 | 100% 符合 JSON Schema |
| 高风险拦截召回 | 极高风险样本召回率 ≥ 95% |
| 误拦截 | 合规原创任务误拦截率 ≤ 10% |
| 用户提示 | 不羞辱用户、不提供规避建议，只引导原创化 |
| 失败回退 | Schema 校验失败时走规则引擎兜底 |

#### 失败回退

1. 模型超时：使用规则引擎关键词匹配。
2. Schema 失败：自动 JSON 修复一次。
3. 修复失败：标记 `manual_review`。
4. 出现仿脸/仿声/搬运/规避平台关键词：默认 `block` 或 `manual_review`。

### 6.7.2 Prompt B：Aha Moment 质量评估 Prompt

#### 使用场景

任务生成完成后，系统自动评估输出是否达到用户可感知价值，决定是否开放结果、自动重试、提示人工优化或补偿。

#### 输入 Schema

```json
{
  "user_profile": {},
  "source_video_summary": "string",
  "content_dna": {},
  "generated_outputs": {
    "report": "string",
    "scripts": ["string"],
    "titles": ["string"],
    "cover_suggestions": ["string"],
    "video_prompts": ["string"]
  },
  "risk_report": {}
}
```

#### 输出 Schema

```json
{
  "aha_score": 0,
  "report_value_score": 0,
  "script_actionability_score": 0,
  "personalization_score": 0,
  "originality_score": 0,
  "risk_clarity_score": 0,
  "pass": false,
  "failure_reasons": ["string"],
  "auto_retry_recommendation": "none|rewrite_scripts|rewrite_titles|rewrite_prompts|full_regeneration",
  "user_visible_summary": "string"
}
```

#### Prompt 模板

```text
你是 AI 短视频爆款增长引擎的输出质量评估 Agent。
请评估本次输出是否能触发用户的第一 Aha Moment：
“用户感觉系统真的把爆款结构转化成了适合自己行业、人设和产品的原创内容”。

评分维度：
1. report_value_score：报告是否解释清楚爆款为什么爆。
2. script_actionability_score：脚本是否可直接拍摄或交给团队改稿。
3. personalization_score：是否结合用户行业、人设、产品和目标受众。
4. originality_score：是否明显区别于原视频，不像洗稿。
5. risk_clarity_score：是否清楚说明可复用和不可复用内容。

请输出 JSON。
如果任一核心分数低于 60，pass=false，并给出 auto_retry_recommendation。
不得为了通过而虚高评分。
```

#### 质量标准

| 指标 | 标准 |
|---|---|
| Aha 总分 | MVP1 完整输出应 ≥ 75 |
| 脚本可用分 | ≥ 70 |
| 个性化分 | ≥ 70 |
| 原创度分 | ≥ 80 |
| 风险清晰度 | ≥ 80 |
| 自动重试 | 低于门槛必须触发对应重试建议 |

## 7. 异常与失败处理

### 7.1 异常分类

| 异常类型 | 示例 | 用户体验 | 系统动作 |
|---|---|---|---|
| 输入异常 | 文件过大、格式不支持、画像缺失 | 明确提示如何修复 | 不扣费或释放冻结 |
| 授权异常 | 未确认授权、疑似未授权素材 | 提示授权要求 | 阻止任务创建 |
| 意图异常 | 用户要求 1:1 复制、仿脸、仿声 | 引导原创化或拦截 | 风控记录 |
| 处理异常 | FFmpeg 失败、抽帧失败 | 提示处理失败 | 自动重试、失败返还 |
| AI 异常 | 模型超时、Schema 失败、幻觉输出 | 自动重试或降级 | 记录模型日志 |
| 质量异常 | 输出空泛、脚本不可用、Prompt 不完整 | 自动重写或提示补偿 | 质量报告 |
| 风控异常 | 相似度过高、品牌/肖像风险 | 强制重构或人工复核 | 风控记录 |
| 计费异常 | 重复扣费、返还失败 | 展示客服入口 | 冻结账户流水并告警 |
| 系统异常 | 队列崩溃、数据库错误 | 系统异常提示 | 告警、回滚、补偿 |

### 7.2 失败处理矩阵

| 失败点 | 自动重试 | 降级方案 | 是否人工介入 | 积分处理 |
|---|---:|---|---:|---|
| 上传失败 | 否 | 重新上传 | 否 | 不扣费 |
| 文件解析失败 | 2 次 | 仅基于用户描述生成低置信度报告，不默认启用 | 可选 | 全额/部分返还 |
| 抽帧失败 | 2 次 | 固定间隔抽帧 | 否 | 不额外扣费 |
| ASR 失败 | 2 次 | 使用 OCR + 视觉理解 | 否 | 降低报告置信度，可部分返还 |
| OCR 失败 | 2 次 | 使用 ASR + 视觉理解 | 否 | 降低报告置信度，可部分返还 |
| 多模态分析失败 | 2 次 | 切换备用模型 | 否 | 失败返还 |
| Content DNA Schema 失败 | 2 次 | JSON 修复 + 重新生成 | 否 | 不额外扣费 |
| 原创脚本低质 | 1-2 次 | 只重写脚本部分 | 否 | 不额外扣费 |
| Prompt 低质 | 1-2 次 | 使用备用 Prompt 模板 | 否 | 不额外扣费 |
| 中高风险 | 不重试 | 强制原创化重构 | 可选 | 按结果扣费 |
| 极高风险 | 不重试 | 阻止生成 | 是 | 按成本部分扣除或返还 |
| 任务超时 | 1 次 | 标记失败 | 可选 | 返还未消耗部分 |
| 用户取消 | 否 | 终止后续步骤 | 否 | 按已消耗成本结算 |

### 7.3 用户可见失败文案示例

#### 7.3.1 风控拦截

```text
当前请求可能涉及高相似复制、未授权素材复用或人物/声音仿制风险，因此无法继续生成同款内容。

你可以改用「强原创重构」模式：系统只学习该视频的内容结构、钩子逻辑和节奏，不复用原视频素材、台词、人物、声音、配乐或商标元素，并重新生成适合你行业和人设的原创脚本。
```

#### 7.3.2 模型失败

```text
本次 AI 分析任务未能稳定完成。系统已自动重试，但仍未达到可交付质量。未消耗的积分将按规则返还，你可以重新上传视频或联系客服转人工处理。
```

#### 7.3.3 质量不足

```text
本次脚本生成质量未达到系统交付标准，系统正在自动重写脚本部分。该重试不会额外扣除你的积分。
```

## 8. 风控与合规

> 本节是产品与工程合规设计要求，不构成法律意见。正式法律条款、地区适配、隐私政策、用户协议、AIGC 标识细节由 D21 专项确认。

### 8.1 合规底线

系统必须坚持：

1. 不直接搬运。
2. 不克隆声音。
3. 不克隆肖像。
4. 不复用原视频素材。
5. 不复用原台词、字幕、配乐、商标。
6. 不绕过平台限制非法抓取。
7. 不生成虚假宣传。
8. 不生成高风险医疗、金融、法律结论性内容。
9. 不帮助用户规避平台风控。
10. 不将产品宣传为“1:1 复刻爆款”。

### 8.2 授权机制

必须在以下节点进行授权确认：

| 节点 | 是否必须 | 说明 |
|---|---:|---|
| 上传视频前 | 必须 | 用户确认素材来源与使用边界 |
| 输入视频链接前 | 必须 | 用户确认仅用于结构学习和原创化 |
| 导出报告前 | 建议 | 再次提示不可复用原素材/台词 |
| 生成 Prompt 前 | 必须 | 提示 Prompt 不得用于仿脸、仿声、搬运 |
| 人工复核前 | 必须 | 用户同意工作人员查看必要内容 |
| 投诉删除时 | 必须 | 记录删除请求与处理结果 |

### 8.3 AIGC 标识预留

MVP1 必须预留：

1. 报告内显式标识：本报告由 AI 辅助生成。
2. 导出文件元数据：记录生成时间、task_id、user_id 哈希、模型版本。
3. 生成内容提示：用户对外发布时应按平台要求添加 AI 辅助生成或 AI 生成说明。
4. 后续视频生成阶段预留水印、元数据、隐式标识能力。
5. 后台可查询任一导出报告的生成来源。

### 8.4 风险分级与动作

| 风险等级 | 判断标准 | 系统动作 | 积分处理 |
|---|---|---|---|
| 低风险 | 结构参考、表达原创、无明显侵权 | 正常生成，记录日志 | 正常扣费 |
| 中风险 | 文案、标题、分镜结构存在相似风险 | 提醒用户，建议原创化改写 | 正常扣费或部分重写 |
| 高风险 | 明显复用文案、镜头、品牌、人物特征 | 强制重构文案、场景、人设、分镜 | 重构成功后扣费 |
| 极高风险 | 仿脸、仿声、未授权素材、明星/影视复刻、违法内容 | 禁止生成，要求授权或人工复核 | 按成本部分扣除或返还 |

### 8.5 风控前置节点

风控不能只在成片后做，MVP1 必须在以下节点前置：

```text
用户输入意图
→ 上传授权确认
→ 视频元数据和水印识别
→ Content DNA 可复用/不可复用判断
→ Creative IR 原创化策略
→ 脚本生成后相似度检查
→ 标题封面虚假宣传检查
→ 视频 Prompt 高风险词检查
→ 报告导出前合规提示
```

### 8.6 人工复核机制

触发人工复核的条件：

1. 用户上传明星、影视、综艺、明显第三方版权内容。
2. 用户明确要求仿脸、仿声、同款复制。
3. 模型判断风险为 `critical`。
4. 用户申诉风控拦截结果。
5. 用户投诉他人侵权或要求删除。
6. 系统出现大额积分补偿争议。
7. 企业客户请求人工审核交付物。

人工复核状态：

```text
pending_review
approved
approved_with_rewrite
rejected
requires_authorization
refunded
deleted
```

### 8.7 投诉与删除机制

MVP1 必须提供基础投诉和删除入口：

| 入口 | 处理 |
|---|---|
| 用户删除自己的上传素材 | 删除或软删除文件，保留必要审计日志 |
| 用户删除生成报告 | 删除用户可见资产，保留计费和安全审计 |
| 第三方投诉侵权 | 创建工单，冻结相关公开导出，进入人工复核 |
| 用户要求数据导出 | 按 D22 数据安全文档执行 |
| 用户要求账号注销 | 删除或匿名化用户相关数据，保留法律/财务必要记录 |

## 12. 不做事项

### 12.1 产品层不做

1. 不把产品定义为“对标账号复刻工具”。
2. 不把产品卖点写成“1:1 复制爆款”。
3. 不承诺“照搬也能不违规、不限流”。
4. 不面向搬运号、影视混剪号、明星仿冒号作为首发核心用户。
5. 不把视频生成当作 MVP1 核心闭环。
6. 不第一版追求全平台账号自动采集。
7. 不第一版追求自动发布。
8. 不第一版做复杂团队协作和模板市场。
9. 不第一版覆盖所有行业和所有平台。
10. 不宣传“保证爆款”“保证涨粉”“保证成交”。

### 12.2 AI 能力不做

1. 不生成仿脸 Prompt。
2. 不生成仿声 Prompt。
3. 不生成可直接搬运原视频的 Prompt。
4. 不复用原视频台词、字幕、配乐、商标、封面。
5. 不输出规避平台审核的建议。
6. 不输出绕过版权检测、搬运检测、限流检测的方法。
7. 不为医疗、金融、法律输出确定性承诺。
8. 不在缺少证据时编造播放量、互动数据、平台趋势。
9. 不允许 Prompt 无 Schema、无版本、无测试直接上线。
10. 不允许模型失败后静默吞错。

### 12.3 工程层不做

1. 不只做前端静态页面。
2. 不用 mock 冒充真实后端能力。
3. 不跳过任务队列。
4. 不跳过积分流水。
5. 不跳过模型成本记录。
6. 不跳过风控日志。
7. 不跳过授权确认。
8. 不跳过后台排查能力。
9. 不把所有 AI 输出存在无约束文本字段里。
10. 不让任务刷新页面后丢失状态。
11. 不让任务失败后无法补偿。
12. 不允许重复回调导致重复扣费。

### 12.4 商业化层不做

1. 不先不可逆扣费再尝试生成。
2. 不忽略失败返还。
3. 不用固定价格覆盖所有成本差异。
4. 不给免费用户无限调用高成本模型。
5. 不允许后台看不到单任务成本。
6. 不允许没有毛利统计就开放大规模付费。
7. 不允许无风控地开放导出。
8. 不允许人工补偿无审计记录。

### 12.5 合规层不做

1. 不绕过平台限制抓取。
2. 不批量下载他人作品。
3. 不复用未授权素材。
4. 不允许用户上传素材不确认授权。
5. 不允许用户投诉或删除请求无入口。
6. 不允许极高风险内容无人工复核机制。
7. 不允许导出内容完全无 AIGC 提示或来源记录。
8. 不允许后台人员无权限边界查看用户素材。

## 2. 文档目标

D17 要解决的是 MVP1 中所有长任务、文件资产、失败补偿和可观测性的工程落地问题。MVP1 的主链路包含上传、元数据解析、抽帧、音频提取、ASR、OCR、镜头切分、多模态理解、Content DNA、Creative IR、原创脚本/标题/封面/视频 Prompt、质检风控、导出、积分扣费和后台记录。这些步骤耗时长、成本高、失败点多，不能放在同步请求中，也不能只做前端假进度。

D17 必须解决：

1. 任务如何从创建、上传、授权、报价、冻结积分到正式入队。
2. 视频处理、AI 生成、风控、导出、清理如何组成可重试、可跳过、可降级的 DAG。
3. 队列如何按 CPU 密集、IO 密集、AI 调用、高成本、清理、补偿分层。
4. 前端、后端、Worker、后台、测试如何共用同一套任务状态、步骤状态、Job 状态和资产状态。
5. 原视频、代理视频、音频、帧、OCR/ASR 文本、证据包、Content DNA、Creative IR、输出包、导出文件如何存储、命名、授权、访问、过期、删除。
6. 失败如何重试、指数退避、死信、补偿、部分成功、人工复核、积分返还。
7. AI 任务如何接入 PromptRun、ModelCallLog、Schema 校验、JSON repair、质量评分、风控门禁。
8. 商业化如何做到任务报价、积分冻结、成本记录、成功扣费、失败返还、部分成功结算、后台毛利统计。
9. 合规如何内建授权、AIGC 标识、风险分级、拦截、人工复核、投诉删除、数据留存和访问审计。
10. AIcoding Agent 如何按统一契约实现，避免各自发明状态、队列、表字段和 Mock 链路。

### 3.2 与 D15/D16 的关系

D15 给出总体架构：模块化单体、异步任务队列、Python 视频/AI Worker、Prompt/模型路由、对象存储、PostgreSQL、Redis、Admin Console 和可观测性。D17 将其中“长任务与资产”固化为状态机、队列拓扑、DAG、对象 Key、生命周期和补偿规则。

D16 是数据库和 API 的最终契约，D17 是任务状态与生命周期的最终口径：

| D17 内容 | D16 承接方式 |

研发规则：如果 D17 定义了某个状态，但 D16 未落库，该状态不得直接进入生产代码；必须先补 D16 迁移和 API 契约。

## 4. 核心结论

### 4.1 一句话结论

MVP1 必须采用 **“主任务状态机 + 步骤级 DAG + 多队列 Worker + 对象存储资产引用 + 幂等补偿事务 + 风控/积分/成本全链路日志”** 的任务与资产架构。任何视频处理、AI 调用、导出、清理、返还和人工复核，都不能绕过统一任务状态机。

### 4.2 MVP1 任务主链路

```text
用户登录
→ 完成 CreatorProfile
→ 上传视频前授权确认
→ 创建 VideoAnalysisTask
→ 生成上传签名 URL
→ 用户直传对象存储
→ 上传完成回调 / 前端确认
→ 文件安全扫描与元数据解析
→ 预估积分并冻结
→ 入队 task.orchestrate
→ 视频处理 DAG：metadata / normalize / audio / asr / frames / ocr / shots / evidence_pack / video_understanding
→ AI 生成 DAG：content_dna / report / creative_ir / deliverables
→ 风控 DAG：quality_check / similarity_check / compliance_check / risk_decision
→ 结算 DAG：credit_capture / refund / partial_settlement
→ 结果资产发布：report / deliverable_pack / export
→ 任务成功、部分成功、失败、人工复核或拦截
→ 生命周期策略：过期、用户删除、投诉删除、审计保留
```

### 4.4 不允许的捷径

1. 不允许前端点击后同步等待完整 AI 生成结果。
2. 不允许 Worker 直接写用户可见结果而不记录 `TaskStepLog`。
3. 不允许 AI 任务绕过 Prompt Registry、Model Router、ModelCallLog、Schema 校验。
4. 不允许视频处理绕过对象存储，把临时文件只存在本地磁盘。
5. 不允许风控失败后仍发布可下载资产。
6. 不允许模型调用失败后无限重试。
7. 不允许扣费成功但任务失败没有返还或补偿记录。
8. 不允许删除用户资产但保留可访问 Signed URL。
9. 不允许后台手动改状态但不记录审计日志。
10. 不允许生产环境使用 Mock Worker 冒充真实 AI 能力。

## 5. 详细设计

### 5.1 总体架构

```text
Frontend Web
  ├─ Task Create / Upload / Consent / Credit Estimate
  ├─ Task Progress / Result / Export / History
  └─ Admin Console

API / BFF Service
  ├─ Auth / RBAC
  ├─ Task API / Asset API / Upload Signed URL API
  ├─ Export API / Billing API / Risk API / Admin API
  └─ Audit Log

Orchestrator Worker
  ├─ Task DAG Builder
  ├─ Dependency Resolver
  ├─ Step Dispatcher
  ├─ Retry / Compensation
  └─ Progress Aggregator

Python Video / AI Worker
  ├─ FFmpeg / Metadata / Normalize
  ├─ Audio / ASR / Frames / OCR / Shot Detection
  ├─ Evidence Pack
  ├─ PromptRun / Model Router
  └─ Schema Validation

Risk / Billing / Lifecycle Worker
  ├─ Quality / Similarity / Compliance
  ├─ Manual Review Queue
  ├─ Credit Capture / Refund
  ├─ Export Generation
  ├─ Asset Cleanup
  └─ Complaint Deletion

Infrastructure
  ├─ PostgreSQL
  ├─ Redis + BullMQ
  ├─ S3/R2/OSS/COS Object Storage
  ├─ OpenTelemetry / Sentry / Structured Logs
  └─ CI/CD / Environment Config
```

### 5.2 四层任务模型

```text
VideoAnalysisTask（用户可见主任务）
  └─ TaskStepLog（业务步骤）
      └─ AsyncJob（队列 Job）
          └─ JobAttempt（一次执行尝试）
```

| 层级 | 面向对象 | 作用 | 用户可见 |
|---|---|---|---|
| `VideoAnalysisTask` | 用户/后台 | 一次完整视频拆解与原创生成任务 | 是 |
| `TaskStepLog` | 前端进度/后台 | 主任务中的业务步骤 | 部分可见 |
| `AsyncJob` | Worker/队列 | 可执行的队列任务 | 后台 |
| `JobAttempt` | 运维/调试 | 某个 Job 的一次执行尝试 | 后台 |

### 5.3 任务步骤与 DAG

| TaskStep | 队列 | 输入 | 输出 |
|---|---|---|---|
| `CONSENT_CHECK` | API/risk.precheck | 用户授权、输入来源 | Consent Snapshot、PreRiskResult |
| `CREDIT_HOLD` | billing.settle | 任务报价、用户余额 | CreditHold |
| `UPLOAD_VALIDATE` | video.metadata | 原视频资产 | Metadata、Validation |
| `NORMALIZE_VIDEO` | video.normalize | 原视频 | ProxyVideo、Thumbnail |
| `EXTRACT_AUDIO` | video.audio | 原视频/代理视频 | AudioAsset |
| `RUN_ASR` | video.asr | AudioAsset | TranscriptSegments |
| `EXTRACT_FRAMES` | video.frames | ProxyVideo | FrameAssets |
| `RUN_OCR` | video.ocr | FrameAssets | OCRSegments |
| `DETECT_SHOTS` | video.shots | ProxyVideo、FrameAssets | ShotSegments |
| `BUILD_EVIDENCE_PACK` | ai.evidence_pack | Metadata、ASR、OCR、Frames、Shots | MultimodalEvidencePack |
| `VIDEO_UNDERSTANDING` | ai.video_understanding | EvidencePack | VideoUnderstandingResult |
| `CONTENT_DNA` | ai.content_dna | VideoUnderstandingResult、EvidencePack | ContentDNA、ShotDNA |
| `REPORT_GENERATION` | ai.content_dna | ContentDNA | AnalysisReport |
| `CREATIVE_IR` | ai.creative_ir | ContentDNA、CreatorProfile | CreativeIR |
| `DELIVERABLES` | ai.deliverables | CreativeIR、CreatorProfile | DeliverablePack |
| `QUALITY_CHECK` | risk.quality | Report、DeliverablePack | QualityCheckReport |
| `SIMILARITY_CHECK` | risk.similarity | Source Evidence、Deliverables | SimilarityCheckReport |
| `COMPLIANCE_CHECK` | risk.compliance | 全部输出、行业、授权 | ComplianceCheckReport |
| `RISK_DECISION` | risk.decision | 风控报告 | RiskDecision |
| `SETTLEMENT` | billing.settle | 任务状态、成本、结果 | Capture/Refund/Partial |
| `EXPORT_REPORT` | export.generate | Report、DeliverablePack | ExportFile |
| `PUBLISH_RESULT` | task.orchestrate | 风控通过的结果资产 | 用户可见结果 |

DAG 依赖：

```text
UPLOAD_VALIDATE
  → NORMALIZE_VIDEO
    → EXTRACT_AUDIO → RUN_ASR
    → EXTRACT_FRAMES → RUN_OCR
    → DETECT_SHOTS
      → BUILD_EVIDENCE_PACK
        → VIDEO_UNDERSTANDING
          → CONTENT_DNA
            → REPORT_GENERATION
            → CREATIVE_IR
              → DELIVERABLES
                → QUALITY_CHECK
                → SIMILARITY_CHECK
                → COMPLIANCE_CHECK
                  → RISK_DECISION
                    → SETTLEMENT
                    → PUBLISH_RESULT
                    → EXPORT_REPORT
```

关键规则：

1. `RUN_ASR`、`RUN_OCR`、`DETECT_SHOTS` 可以并行。
2. `RUN_ASR` 失败但 OCR 有效，可降级为 OCR 主导。
3. `RUN_OCR` 失败但 ASR 完整，可降级为 ASR 主导。
4. `DETECT_SHOTS` 失败可降级为按时间窗口切片。
5. `BUILD_EVIDENCE_PACK` 必须至少有视觉证据与一种文本证据。
6. `RISK_DECISION` 未完成前不得对用户发布最终可复制、可导出的输出包。
7. `SETTLEMENT` 必须幂等。
8. `EXPORT_REPORT` 可在成功后由用户触发，MVP1 优先 Markdown/HTML。

## 6.5 文件存储与资产生命周期

### 6.5.1 Bucket / Prefix

| Bucket / Prefix | 内容 | 访问级别 |

## 6.6 AI 任务接入规则

D17 不定义 Prompt 内容，但所有 AI 任务必须满足：

1. 必须有 `prompt_template_id` 和 `prompt_version_id`。
2. 必须有输入 Schema 和输出 JSON Schema。
3. 必须创建 `PromptRun`。
4. 必须走 `ModelRouter` 并记录 `ModelCallLog`。
5. 必须支持 JSON Repair。
6. 必须接入质量门禁和风控门禁。
7. 低置信度输出不得直接发布。
8. 高成本 AI 任务必须有关联 `CreditHold` 和 `CostLedger`。

AI 失败回退：

| 失败类型 | 处理 |
|---|---|
| JSON 解析失败 | JSON repair 一次；失败后同模型重试；仍失败切换备选模型 |
| Schema 字段缺失 | 自动补全 Prompt；仍缺失则降级输出并标记低置信度 |
| 模型超时 | 指数退避重试；供应商熔断后路由备选模型 |
| 模型内容安全拒绝 | 记录拒绝原因，触发风控/人工复核 |
| 输出相似度过高 | 自动原创化重写一次；仍高风险则人工复核或拦截 |
| 输出质量低 | 重写或部分成功，低质量部分不扣用户积分 |
| 成本超过预估 | 停止追加高成本步骤，进入人工/降级策略 |

## 7. 异常与失败处理

### 7.1 错误分类

| 错误类别 | 示例 | 用户责任 | 是否重试 | 积分处理 |
|---|---|---:|---:|---|
| `USER_INPUT_INVALID` | 文件格式不支持、时长超限 | 是 | 否 | 不冻结或返还 |
| `USER_CONSENT_MISSING` | 未确认授权 | 是 | 否 | 不冻结 |
| `RISK_PRECHECK_BLOCKED` | 明确仿脸仿声/搬运意图 | 是 | 否 | 不冻结或返还 |
| `UPLOAD_FAILED` | 上传中断 | 可能 | 用户重试 | 不扣费 |
| `STORAGE_UNAVAILABLE` | 对象存储故障 | 否 | 是 | 失败返还 |
| `VIDEO_PROCESSING_FAILED` | FFmpeg 失败 | 可能 | 是/降级 | 视阶段 |
| `ASR_FAILED` | 音频转写失败 | 否 | 是/降级 | 可部分成功 |
| `OCR_FAILED` | OCR 失败 | 否 | 是/降级 | 可部分成功 |
| `MODEL_PROVIDER_TIMEOUT` | 模型超时 | 否 | 是 | 不重复扣费 |
| `MODEL_OUTPUT_SCHEMA_INVALID` | JSON 不合法 | 否 | Repair/重试 | 不重复扣费 |
| `QUALITY_GATE_FAILED` | 输出质量不足 | 否 | 重写/降级 | 平台质量成本 |
| `SIMILARITY_RISK_HIGH` | 相似度高 | 可能 | 重写/复核 | 默认不扣高风险输出 |
| `COMPLIANCE_BLOCKED` | 合规拦截 | 可能 | 否/复核 | 返还或部分结算 |
| `CREDIT_HOLD_FAILED` | 余额不足/冻结失败 | 用户 | 否 | 不执行 |
| `CREDIT_CAPTURE_FAILED` | 扣费事务失败 | 否 | 是 | 暂不发布或结算异常 |
| `UNKNOWN_SYSTEM_ERROR` | 未知异常 | 否 | 是/死信 | 失败返还 |

### 7.2 重试策略

| 队列 | 最大重试 | 退避策略 | 是否可降级 |
|---|---:|---|---|
| `video.metadata` | 2 | 30s, 2m | 否 |
| `video.normalize` | 2 | 1m, 5m | 可生成低码率代理 |
| `video.audio` | 2 | 1m, 5m | 可跳过音频 |
| `video.asr` | 3 | 1m, 5m, 15m | 可 OCR 主导 |
| `video.frames` | 2 | 1m, 5m | 可降低帧率 |
| `video.ocr` | 3 | 1m, 5m, 15m | 可 ASR 主导 |
| `video.shots` | 2 | 1m, 5m | 可时间窗口切片 |
| `ai.*` | 2-3 | 1m, 5m, 15m | 可换模型/降级 |
| `risk.*` | 2 | 1m, 5m | 不可跳过，失败转人工 |
| `billing.*` | 5 | 10s, 30s, 2m, 5m, 15m | 不可跳过 |
| `export.generate` | 2 | 30s, 2m | 用户可重试 |

禁止重试：文件类型不支持、用户未授权、明确仿脸仿声/搬运/绕平台请求、余额不足、用户主动取消、投诉成立、幂等请求已成功、风控最终拦截且不允许改写。

### 7.3 死信队列

进入 `dead_letter` 的条件：超过最大重试、Worker 心跳丢失、状态机非法迁移、计费补偿失败、对象存储删除失败、风控任务超 SLA、任务状态与资产状态不一致。

死信处理必须记录原因、告警、标记用户可见状态、处理冻结积分、支持 Admin Replay、保留旧日志，且进入 D19 监控和 D23 运维 SOP。

### 7.4 幂等与补偿

| 场景 | 幂等键 |
|---|---|
| 创建任务 | `user_id + client_idempotency_key` |
| 完成上传 | `asset_id + content_hash` |
| 冻结积分 | `task_id + quote_version + hold` |
| 入队步骤 | `task_id + step_key + step_version` |
| 模型调用 | `prompt_run_id + model_route_decision_id` |
| 生成资产 | `task_id + asset_type + step_key + version` |
| 扣费 | `task_id + settlement_version + capture` |
| 返还 | `task_id + failure_code + refund` |
| 删除资产 | `asset_id + delete_reason` |

补偿动作：冻结成功但任务未入队则释放冻结；视频处理失败则返还生成类积分；AI 部分失败则允许部分成功，未生成部分不扣费；风控拦截默认返还主要生成积分；扣费失败则结果暂不发布或标记结算异常；投诉成立则下架资产并按规则返还相关积分。

### 7.5 部分成功

允许：仅拆解报告成功、报告+部分脚本成功、ASR 失败但 OCR 有效、OCR 失败但 ASR 有效、导出失败但页面结果成功。

不允许：风控未完成、授权未确认、相似度高风险未处理、计费不一致、缺少 AIGC/原创化/风险提示。

## 8. 风控与合规

### 8.1 授权确认

创建任务前必须保存授权快照：`consent_id`、`task_id`、`user_id`、`source_type`、`declared_rights`、`allowed_usage`、`disallowed_usage_ack`、`aigc_notice_ack`、`complaint_policy_ack`、`created_at`、`ip_hash`、`user_agent_hash`。未确认授权不得上传、不得冻结积分、不得进入队列。

### 8.2 风险分级与动作

| 风险等级 | 示例 | 任务动作 | 资产动作 | 积分动作 |
|---|---|---|---|---|
| `LOW` | 普通口播/探店/知识分享 | 正常执行 | 正常发布 | 成功扣费 |
| `MEDIUM` | 有对标元素、强相似结构 | 执行并加强原创化 | 展示风险提示 | 成功扣费 |
| `HIGH` | 疑似搬运、品牌/人物/台词高度相似 | 转人工复核或自动重写 | 隔离结果 | 暂不扣最终费用 |
| `BLOCKED` | 仿脸仿声、未授权素材复用、规避平台 | 直接拦截 | 不发布/删除 | 返还或不冻结 |

### 8.3 AIGC 标识

所有 AI 生成的用户可见交付物必须携带生成时间、AI 生成标识、Prompt/模板版本摘要、风险提示、原创化说明、不可复用清单。MVP1 Markdown/HTML 导出必须默认包含：

```text
本报告与内容建议由 AI 基于用户提交素材进行结构化分析与原创化生成，仅用于内容策划参考。请勿直接复制他人受版权保护的素材、台词、人物形象、声音、商标、封面或其他可识别表达。发布前请结合自身授权、平台规则和行业合规要求进行人工审核。
```

### 8.4 人工复核触发

触发条件：风控总等级为 `HIGH`、相似度超过阈值但可重写、用户行业高风险且输出包含承诺性表达、模型拒绝或内容安全警告、证据包置信度低、用户投诉、后台抽检命中、成本异常或多次失败需要补偿判断。

人工复核期间：用户结果页显示等待复核；不展示可复制最终输出；资产进入 `QUARANTINED`；积分保持冻结或按 D20 规则释放；超 SLA 进入客服补偿队列。

### 8.5 投诉删除机制

```text
投诉提交
→ 创建 ComplaintCase
→ 相关资产暂时 Quarantine
→ 人工复核
→ 投诉成立：删除/下架资产 + 撤销下载 URL + 记录 AuditLog + 必要时补偿
→ 投诉不成立：恢复资产 + 记录复核结论
```

D17 必须提供资产级删除能力，不能只删除任务页面记录。

### 8.6 数据安全

对象存储默认私有；Signed URL 短期有效；后台访问必须 RBAC；日志不得记录完整 Prompt、用户隐私字段、可复原原视频 URL；PromptRun 和 ModelCallLog 保存摘要、哈希、版本、成本和必要调试信息；用户删除后不得通过历史导出文件访问；审计保留只保留最小必要信息。

### 9.1 单元测试

|---|---|

| 积分补偿 | 失败、取消、拦截、部分成功规则正确 |

### 9.2 集成测试

| 场景 | 验收标准 |
|---|---|
| 上传成功 → 任务入队 | 资产状态、任务状态、步骤日志正确 |
| 视频处理全成功 | 所有处理资产入库，EvidencePack 可用 |
| ASR 失败降级 OCR | 任务继续，状态标记降级 |

| 任务取消 | 未执行步骤不再入队，积分释放 |
| 重复 Start 请求 | 不重复冻结积分，不重复入队 |

### 9.3 E2E 主路径验收

1. 用户登录并完成 CreatorProfile。
2. 创建任务、确认授权、上传 30-60 秒竖屏 MP4。
3. 系统完成积分预估和冻结。
4. 队列执行视频处理。
5. 生成 Content DNA、Creative IR、5 条原创脚本、10 个标题、3 个封面建议、3 个视频 Prompt。
6. 完成质检风控并成功扣费。
7. 用户查看结果并导出 Markdown/HTML。
8. 后台可查看任务、步骤、资产、成本、积分、风控日志。
9. 用户删除任务后资产不可再访问。

### 9.4 故障演练

必须覆盖 Redis 不可用、Worker 宕机、心跳丢失、对象存储上传失败、对象存储删除失败、模型供应商超时、风控服务失败、扣费服务失败、清理任务误命中保护、后台手动重试。

### 9.5 上线阻断条件

出现以下情况不得上线：

1. 任务状态机存在非法迁移且无测试覆盖。
2. 积分可能重复扣费或失败不返还。
3. 风控失败后仍可能展示可复制输出。
4. 用户删除后 Signed URL 仍可访问。
5. 原视频或导出文件公开可访问。
6. Worker 失败无法进入死信或后台不可见。
7. AI 输出无 PromptRun / ModelCallLog / Schema 校验记录。
8. 任务成功但后台无法看到成本、步骤、风险、积分。
9. 生产环境默认使用 mock。
10. 未经过 E2E 主路径测试和故障演练。

## 12. 不做事项

MVP1 D17 明确不做：

1. 不做对标账号全量自动抓取队列。
2. 不做绕平台限制的数据采集和批量下载。
3. 不做自动发布到短视频平台。
4. 不做完整视频生成和成片拼接队列；仅为 MVP3 预留 `generation.*` 命名空间，不进入生产主流程。
5. 不做仿脸、仿声、人物身份模拟、明星/影视/综艺复刻资产链路。
6. 不做公开永久下载链接。
7. 不做跨用户共享素材库。
8. 不做复杂素材市场和模板市场生命周期。
9. 不做移动端离线任务。
10. 不做多区域对象存储容灾的复杂实现；MVP1 只要求 Adapter 抽象可迁移。
11. 不做实时 WebSocket 强依赖；MVP1 可用轮询，SSE/WebSocket 后置。
12. 不做完整 PDF/DOCX 导出；MVP1 优先 Markdown/HTML。
13. 不做自动替换生产 Prompt；Prompt 进化必须走后续文档和人工/Benchmark 门禁。
14. 不做生产环境 mock 任务。
15. 不做用户看不到但无法删除的大量原始视频长期留存。
16. 不做没有 AuditLog 的后台强制状态修改。
17. 不做失败后人工线下补偿而系统无记录的流程。
18. 不做任务状态和资产状态由各模块自行定义。

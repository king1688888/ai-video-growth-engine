## 2. 文档目标

### 2.1 本文档要解决的问题

D18 要解决的是 MVP1 从“能跑通 AI 工作流”升级为“能安全、合规、可控地处理用户数据和生成资产”的工程问题。本项目会处理用户上传视频、对标链接、账号画像、行业信息、产品卖点、ASR/OCR 文本、抽帧图片、Content DNA、Creative IR、原创脚本、视频 Prompt、模型调用日志、积分流水、支付订单、后台复核记录和投诉删除记录。如果没有 D18，系统会出现以下风险：

1. 用户上传视频和抽帧文件无权限控制，被越权访问。
2. 后台管理员权限过大，可随意查看用户资产和 Prompt。
3. 模型调用日志包含用户隐私、商业信息或原始素材片段，长期裸存。
4. 第三方模型供应商的数据传输、留存和训练使用边界不清晰。
5. 用户删除数据后，派生的 ASR/OCR、Content DNA、Creative IR、导出文件仍残留。
6. 积分交易、模型成本、风控复核和投诉处理无法审计。
7. AIcoding Agent 为了赶进度跳过权限、日志、脱敏、删除、审计和测试。
8. 企业客户无法接受数据治理水平，影响商业化成交。
9. 发生安全事故时无法定位影响范围、无法通知用户、无法补救。

因此 D18 必须把以下能力落成工程系统：

```text
用户授权与隐私确认
→ 数据分类分级
→ 资产安全存储
→ RBAC + ABAC 权限控制
→ 文件签名访问
→ 敏感字段脱敏
→ AI 模型数据传输治理
→ 审计日志与后台操作日志
→ 数据导出 / 删除 / 留存 / 清理
→ 安全异常检测与事故响应
→ 测试验收与上线门禁
```

### 2.3 本文档的研发落点

D18 最终必须落到以下工程对象：

1. 数据分类分级枚举：`DataSensitivityLevel`、`DataDomain`、`AssetPrivacyLevel`。
2. 权限模型：`Role`、`Permission`、`RolePermissionBinding`、`OrgMembership`、`AccessPolicy`。
3. 隐私授权：`ConsentRecord`、`AuthorizationConfirmation`、`DataProcessingRecord`。
4. 数据资产治理：`DataAsset`、`DataLineageEdge`、`DataRetentionPolicy`、`DataDeletionJob`、`DataExportJob`。
5. 文件访问控制：对象存储私有桶、短期签名 URL、下载权限校验、导出文件过期策略。
6. 日志与审计：`AuditLog`、`AdminActionLog`、`AccessLog`、`SecurityEvent`。
7. 模型数据传输记录：`ModelDataTransferLog`、供应商数据策略配置、零训练/零留存标记。
8. 安全事故处理：`PrivacyIncident`、`IncidentAction`、影响范围评估、通知记录。
9. 安全后台页面：角色权限管理、资产访问日志、删除导出任务、模型传输日志、安全事件。
10. AI 辅助能力：数据分类、PII 检测、脱敏建议、访问异常摘要、事故摘要 Prompt 与评测。
11. 自动化测试：权限矩阵测试、越权测试、数据删除级联测试、签名 URL 过期测试、审计日志测试、模型传输脱敏测试。
12. AIcoding 任务拆分和可复制执行提示词。

## 4. 核心结论

### 4.1 MVP1 安全设计原则

MVP1 必须采用「默认私有、最小权限、全链路审计、可删除、可追溯、可补偿」原则。

1. 所有用户上传视频、抽帧、音频、ASR/OCR、Content DNA、Creative IR、输出包、导出文件默认私有。
2. 所有文件必须放在私有对象存储桶，通过短期签名 URL 访问，不允许公开 URL。
3. 所有后台查看用户资产的行为必须记录审计日志，默认只显示脱敏摘要。
4. 所有模型调用必须记录供应商、模型、Prompt 版本、输入摘要、输出摘要、成本、延迟、数据传输策略。
5. 用户内容默认不得用于模型训练、内部样本集、公开案例或营销展示，除非用户明确授权。
6. 用户请求删除时，必须级联删除原始资产、派生资产、导出文件和可识别内容；必要的账务、风控和审计日志只保留最小化脱敏记录。
7. 高风险资产、投诉资产、人工复核资产必须进入隔离状态，停止导出、分享、二次生成和模型重跑。
8. 积分扣费、返还、人工补偿必须可追溯到任务、模型调用和风控决策。

### 4.2 P0 必须实现的安全能力

MVP1 P0 必须实现：

1. 用户登录鉴权。
2. 组织与用户基础 RBAC。
3. 用户上传资产私有化存储。
4. 文件签名 URL。
5. 上传授权确认记录。
6. AIGC 标识确认记录。
7. 数据分类分级字段。
8. 后台角色权限控制。
9. 用户资产访问权限校验。
10. 任务、模型调用、积分、风控、后台操作审计日志。
11. 用户数据导出申请。
12. 用户数据删除申请。
13. 删除任务级联处理。
14. 敏感字段脱敏显示。
15. 第三方模型数据传输日志。
16. 安全事件记录与后台查看。
17. 权限矩阵自动化测试。

### 4.3 P1/P2 预留能力

P1/P2 可预留但不进入 MVP1 默认主流程：

1. 企业 SSO / SAML / OIDC。
2. 企业级多组织、多空间、多项目权限。
3. 细粒度字段级加密。
4. 完整 DLP 扫描。
5. 数据驻留区域选择。
6. 企业客户独立模型供应商配置。
7. BYOK / 客户自带密钥。
8. 权限审批工作流。
9. 自动化安全风险评分。
10. 合规报表自动生成。

### 4.4 安全与商业化的关系

D18 不直接定义价格套餐，但必须支撑商业化：

1. 高成本 AI 任务只有在授权确认、风险预检、积分预估、余额检查通过后才能执行。
2. 因权限、授权、风控前置失败而未进入高成本处理的任务，不扣积分或释放冻结积分。
3. 因系统安全策略、模型供应商策略、对象存储失败、权限配置错误导致任务失败，应按 D20 规则返还积分并记录内部成本。
4. 数据导出、删除、投诉处理在 MVP1 不建议单独收费；企业级合规报告可作为后续商业化增值能力。
5. 所有积分扣费、失败返还和人工补偿必须有审计日志，避免财务争议。

## 5. 详细设计

### 5.1 数据治理总流程

```text
用户注册 / 登录
→ 完成用户画像
→ 用户上传视频 / 输入链接 / 导入数据
→ 授权与隐私确认
→ 系统创建 DataAsset
→ 系统进行数据分类分级
→ 系统生成私有存储对象和访问策略
→ 任务执行：视频处理 / AI 生成 / 风控 / 导出
→ 每一步写入 TaskLog、ModelCallLog、AuditLog、CostLedger
→ 输出资产进入权限控制和生命周期管理
→ 用户可查看、导出、删除自己的数据
→ 投诉或高风险时进入隔离 / 人工复核 / 删除流程
```

### 5.2 数据分类分级

| 等级 | 枚举值 | 定义 | 示例 | 默认访问策略 | 存储要求 | 日志要求 |
|---|---|---|---|---|---|---|
| L0 | `PUBLIC` | 可公开展示且不含用户隐私 | 官网介绍、公开模板说明 | 所有人可读 | 普通存储 | 普通日志 |
| L1 | `INTERNAL` | 内部配置或非敏感运营数据 | 行业配置、Prompt 名称、任务统计聚合 | 员工按角色可读 | 私有存储 | 后台操作日志 |
| L2 | `USER_PRIVATE` | 用户私有业务数据 | 用户画像、上传链接、任务结果、脚本输出 | 仅数据 owner、组织授权成员和受控后台角色可访问 | 私有存储，访问鉴权 | 审计日志 |

### 5.5 权限模型总设计

D18 使用 RBAC + ABAC 混合模型：

- RBAC 决定用户或后台人员是否有某类操作权限。
- ABAC 根据组织、资产归属、数据等级、任务状态、风险状态、访问目的和时间限制做二次判断。

权限判断必须满足：

```text
is_authenticated
AND role_has_permission(action, resource_type)
AND abac_policy_allows(actor, action, resource, context)
AND resource_not_quarantined_unless_reviewer
AND signed_url_not_expired_if_file_access
AND audit_log_written_for_sensitive_access
```

### 5.6 角色定义

| 组织管理员 | `ORG_ADMIN` | 团队/企业空间 | 管理任务、成员基础权限、查看组织资产，不能查看 L4 数据 |

| AI Worker | `AI_WORKER` | 服务内部 | 读取必要证据包、调用模型、写入 AI 输出，不可访问支付密钥和全量用户数据 |

### 6.6 状态机

#### 6.6.1 数据资产状态

```text
created
→ classified
→ active
→ restricted / quarantined
→ deletion_requested
→ deleting
→ deleted
```

特殊状态：

- `restricted`：权限受限，但未进入风险隔离。
- `quarantined`：投诉、高风险或人工复核状态，不允许导出和二次生成。
- `deleted`：物理删除或逻辑删除完成，用户不可访问。

#### 6.6.2 数据导出状态

```text
queued
→ running
→ ready
→ downloaded / expired
```

失败状态：

- `failed_retryable`
- `failed_final`

#### 6.6.3 数据删除状态

```text
queued
→ running
→ completed
```

异常状态：

- `partial_failed`：部分派生资产删除失败，需要后台处理。
- `blocked`：因账务、投诉、法务保全或安全事故暂不能完全删除，只能脱敏隐藏。
- `failed`：系统错误，需要重试或人工介入。

### 6.7 AI 能力设计

D18 涉及的 AI 能力只作为安全治理辅助，不允许替代硬规则和人工审批。

#### 6.7.1 P18_DATA_CLASSIFICATION Prompt

用途：对新建资产或文本字段进行数据域、敏感等级和风险标签初判。

输入 Schema：

```json
{
  "asset_id": "uuid",
  "asset_type": "uploaded_video | transcript | ocr_text | content_dna | creative_ir | deliverable | model_log",
  "text_preview_redacted": "string",
  "metadata": {
    "mime_type": "string",
    "source_task_type": "string",
    "user_segment": "string",
    "industry": "string"
  }
}
```

输出 Schema：

```json
{
  "data_domain": "UPLOAD_ASSET | VIDEO_EVIDENCE | AI_INTERMEDIATE | DELIVERABLE | RISK_COMPLIANCE | BILLING | IDENTITY | CREATOR_PROFILE",
  "sensitivity_level": "PUBLIC | INTERNAL | USER_PRIVATE | SENSITIVE | RESTRICTED",
  "risk_tags": ["contains_personal_info", "contains_face", "contains_contact", "contains_payment", "contains_unlicensed_media", "contains_minor", "contains_health_finance_legal"],
  "confidence_score": 0.0,
  "reasoning_summary": "不超过100字的判断摘要",
  "recommended_actions": ["mask", "quarantine", "manual_review", "allow"]
}
```

质量标准：

1. 输出 JSON 合法率 ≥ 99%。
2. 对联系方式、支付信息、身份证件、密钥等高敏内容召回率 ≥ 95%。
3. 高风险误放率必须低于 2%。
4. 低置信度 `<0.75` 必须按更高等级处理或进入人工复核。

失败回退：

1. AI 分类失败时，默认按 `SENSITIVE` 处理。
2. Schema 校验失败时，触发 JSON repair；仍失败则使用规则分类。
3. 不允许因 AI 未识别而降低权限。

#### 6.7.2 P18_PII_DETECTION_REDACTION Prompt

用途：对 ASR/OCR、PromptRun 输入输出、后台摘要进行 PII 检测和脱敏建议。

输出 Schema：

```json
{
  "contains_pii": true,
  "pii_items": [
    {
      "type": "phone | email | address | id_number | payment | face_description | account_id | api_key | other",
      "span_hint": "string",
      "redaction_strategy": "mask | remove | hash | replace_with_placeholder",
      "risk_level": "low | medium | high | critical"
    }
  ],
  "redacted_text": "string",
  "confidence_score": 0.0
}
```

失败回退：

1. 使用正则规则识别手机号、邮箱、URL、密钥模式。
2. 日志展示默认使用结构化摘要，不展示完整原文。
3. 对密钥疑似泄露直接创建 `SECRET_EXPOSURE` 安全事件。

#### 6.7.3 P18_ACCESS_ANOMALY_SUMMARY Prompt

用途：对审计日志聚合结果生成异常访问摘要，辅助安全管理员排查。

## 7. 异常与失败处理

### 7.1 授权缺失

| 场景 | 处理 |
|---|---|
| 用户未同意隐私政策 | 禁止创建 AI 任务，引导到授权页 |
| 用户未确认上传素材授权 | 禁止积分冻结和模型调用 |
| 用户不同意第三方模型处理 | 允许保存草稿，但禁止调用外部模型；提示当前版本无法完成自动拆解 |
| 授权版本过期 | 要求重新确认后继续 |

### 7.2 越权访问

处理流程：

1. API 返回 `403_ACCESS_DENIED`。
2. 不泄露资源是否存在、所属用户、文件名、任务标题等敏感信息。
3. 写入 `audit_logs`。
4. 连续多次越权触发 `ACCESS_DENIED` 安全事件。
5. 管理后台展示聚合告警。

### 7.3 签名 URL 失效

处理流程：

1. 前端提示“访问链接已过期，请刷新后重试”。
2. 后端重新进行权限校验后生成新 URL。
3. 不允许前端缓存长期 URL。
4. 导出文件过期后必须重新申请导出。

### 7.4 删除任务失败

| 失败类型 | 处理 |
|---|---|
| 对象存储删除失败 | 重试 3 次，进入 `partial_failed`，创建安全事件 |
| 派生资产关系缺失 | 使用 `task_id` 和 `owner_user_id` 兜底扫描 |
| 审计/账务记录不可删除 | 脱敏保留，向用户解释必要保留范围 |
| 正在处理的任务 | 先取消任务，再删除已生成资产 |
| 风险/投诉保全 | 进入 `blocked`，仅隐藏用户可见内容，等待合规处理 |

### 7.5 模型供应商数据策略不满足

处理流程：

1. `Model Router` 在调用前检查供应商策略。
2. 若供应商不支持禁止训练或零留存，且请求含 L3/L4 数据，则阻断。
3. 返回 `MODEL_TRANSFER_POLICY_BLOCKED`。
4. 若可降级到本地模型或低风险摘要，则走降级路径。
5. 未实际调用高成本模型时，释放冻结积分。

### 7.6 日志写入失败

审计日志是安全关键路径。处理规则：

1. 对 L3/L4 数据访问，若审计日志写入失败，默认拒绝访问。
2. 对普通 L1/L2 操作，可进入延迟写入队列，但必须有本地 fallback buffer。
3. 审计队列积压超过阈值时，后台告警并限制高敏访问。

### 7.7 积分与安全失败联动

| 失败点 | 是否扣费 | 处理 |
|---|---:|---|
| 授权缺失导致任务未开始 | 否 | 不冻结或释放冻结积分 |
| 权限校验失败 | 否 | 不扣费，记录安全事件 |
| 模型传输策略阻断 | 否 | 释放冻结积分，提示原因 |
| 视频处理已完成但风控隔离 | 可部分扣费，按 D20 | 展示可交付部分或进入人工复核 |
| 系统安全错误导致任务失败 | 否 | 全额返还冻结积分，记录内部成本 |
| 用户主动删除任务 | 已产生模型成本时按 D20 | 取消后续步骤，删除资产 |

## 8. 风控与合规

### 8.1 授权机制

MVP1 至少包含四类授权：

1. 用户协议与隐私政策确认。
2. 上传素材授权确认。
3. AIGC 辅助生成与用户发布自审确认。
4. 第三方模型处理确认。

默认不开启：

1. 营销案例授权。
2. Benchmark 样本授权。
3. 用于模型训练授权。

### 8.2 AIGC 标识

输出包和导出报告必须包含：

```text
本报告和内容方案由 AI 辅助生成，仅用于爆款结构学习、原创化创作参考。发布前请确认素材授权、事实准确性、平台规则和行业合规要求。系统不提供搬运、克隆、洗稿、仿脸、仿声或规避平台审核能力。
```

### 8.3 风险分级与权限联动

| 风险等级 | 触发条件 | 权限动作 |
|---|---|---|
| R0 低风险 | 普通企业 IP、本地商家内容，未命中敏感 | 正常处理 |
| R1 轻风险 | 含联系方式、品牌名、轻微相似表达 | 脱敏提示，继续处理 |
| R2 中风险 | 可能含未授权素材、明显复用原文案、强营销承诺 | 降级处理、重写、提示用户 |
| R3 高风险 | 仿脸仿声、影视明星、医疗金融法律承诺、疑似搬运 | 阻断或转人工复核 |
| R4 严重风险 | 密钥泄露、支付数据、个人身份证件、投诉资产、违法内容 | 隔离、禁止访问、触发安全事件 |

### 8.4 拦截策略

1. 输入阶段命中 R3/R4：禁止进入高成本模型调用。
2. 处理阶段发现高风险资产：中止后续任务，隔离资产。
3. 输出阶段相似度过高：要求自动重写或人工复核。
4. 投诉阶段：立即下架相关导出与分享能力，进入人工复核。
5. 删除阶段：按数据血缘删除派生资产。

### 8.5 人工复核

人工复核员可查看的内容应按必要性最小化：

1. 默认查看脱敏摘要、风险标签、证据时间戳。
2. 只有当摘要不足以判断时，才能申请查看敏感原始片段。
3. 每次查看敏感片段必须填写 `access_purpose`。
4. 所有查看、下载、判定、解除隔离动作必须写入审计日志。

### 8.6 投诉删除机制

投诉来源：

1. 用户本人。
2. 权利人。
3. 平台通知。
4. 内部风控发现。

处理流程：

```text
收到投诉
→ 创建 ComplaintCase
→ 标记关联资产为 quarantined
→ 禁止导出 / 分享 / 二次生成
→ 风控复核
→ 确认删除 / 驳回 / 保留证据
→ 级联删除或脱敏隐藏
→ 记录处理结论
→ 必要时执行积分补偿或用户通知
```

### 8.7 第三方模型数据传输治理

每个模型供应商必须配置：

| 配置 | 必填 | 说明 |
|---|---:|---|
| `provider_code` | 是 | 供应商编码 |
| `supported_data_levels` | 是 | 允许处理的最高数据等级 |
| `zero_retention_supported` | 是 | 是否支持零留存 |
| `training_opt_out_supported` | 是 | 是否支持不用于训练 |
| `region` | 是 | 处理区域 |
| `log_policy` | 是 | 请求/响应日志策略 |
| `data_processing_terms_url` | P1 | 数据处理条款链接 |
| `enabled_for_sensitive_data` | 是 | 是否允许 L3 数据 |
| `enabled_for_restricted_data` | 是 | 默认否 |

规则：

1. L4 数据禁止发送第三方模型。
2. L3 数据必须使用支持禁止训练和低留存策略的供应商。
3. PromptRun 日志默认不保存完整敏感输入输出。
4. 供应商配置变更必须记录审计日志。

## 9. 测试与验收标准

### 9.1 单元测试

| 测试项 | 验收标准 |
|---|---|
| RBAC 权限判断 | 每个角色的 allow/deny 用例覆盖 100% P0 权限 |
| ABAC 策略 | org_id、owner、risk_status、sensitivity_level、expires_at 均有测试 |
| 数据分类规则 | L3/L4 规则分类准确，AI 失败时默认升高等级 |
| 签名 URL | 过期、权限不足、隔离资产均不可访问 |
| 脱敏工具 | 邮箱、手机号、地址、密钥、支付信息脱敏通过 |
| 审计日志 | 高敏访问无日志则拒绝访问 |

### 9.2 API 测试

必须覆盖：

1. 未登录访问所有安全 API 返回 401。
2. 非 owner 访问资产返回 403。
3. 组织成员按角色访问资产。
4. 客服默认不可查看原视频。
5. 风控复核员访问隔离资产必须写审计日志。
6. 用户可申请导出自己的数据。
7. 用户可申请删除自己的任务资产。
8. 删除后原文件签名 URL 失效。
9. 导出文件过期后不可下载。
10. 模型传输策略阻断高敏数据。

### 9.3 E2E 测试

#### E2E-SEC-01：正常用户主流程

```text
注册登录
→ 同意隐私政策
→ 完成画像
→ 上传视频
→ 确认授权
→ 创建任务
→ 生成报告
→ 查看输出包
→ 导出报告
→ 申请删除任务
→ 确认资产和派生资产不可访问
```

验收：全流程通过，所有关键步骤有审计日志和数据资产记录。

#### E2E-SEC-02：越权访问

```text
用户 A 创建任务
→ 用户 B 尝试访问任务报告和文件 URL
→ 系统拒绝
→ 后台产生 ACCESS_DENIED 记录
```

验收：不泄露资源细节，不生成可用签名 URL。

#### E2E-SEC-03：后台敏感访问

```text
客服查看用户任务失败原因
→ 只能看到摘要
→ 尝试打开原视频失败
→ 风控复核员填写访问目的后查看必要证据
→ 审计日志完整记录
```

验收：客服不可越权，复核员访问全留痕。

#### E2E-SEC-04：模型传输阻断

```text
上传疑似高敏素材
→ 数据分类为 RESTRICTED
→ 进入模型调用前被阻断
→ 释放积分冻结
→ 任务提示转人工或删除
```

验收：无外部模型调用，无扣费，ModelDataTransferLog 标记 blocked。

### 9.4 安全测试

| 项目 | 通过标准 |
|---|---|
| OWASP 基础测试 | 无高危漏洞 |
| SQL 注入 | 全部参数化，测试用例阻断 |
| XSS | 输出包、报告、后台备注均转义或清洗 |
| CSRF | 管理类接口有防护 |
| Rate Limit | 登录、签名 URL、导出删除、后台查询有限流 |
| Secret Scan | 仓库无明文密钥 |
| 依赖漏洞 | 无 critical/high 未处理漏洞 |
| 权限绕过 | 所有敏感 API 服务端校验，不依赖前端隐藏按钮 |

### 9.5 上线验收门槛

MVP1 上线前必须满足：

1. P0 权限矩阵测试通过率 100%。
2. L3/L4 敏感数据访问均有审计日志。
3. 对象存储无公开读写桶。
4. 签名 URL 有过期时间且不可被复用提升权限。
5. 用户删除任务能级联删除原始资产和派生资产。
6. PromptRun / ModelCallLog 不保存未脱敏的高敏完整正文。
7. 后台客服默认不可查看原始视频和完整 Prompt。
8. 模型供应商配置包含训练禁用和留存策略字段。
9. 安全事件有后台可查看入口。
10. 生产环境 mock 安全能力默认关闭。

# AI 自媒体商业化产品文档体系与 AIcoding 工程研发顺序 - 最终复盘版

> 适用项目：AI 自媒体对标账号拆解、原创化生成与数据进化系统  
> 适用目标：支撑 ChatGPT Project 分文档深度设计、Manus / Codex / Claude Code / Claude Code Agent 自动化研发、工程级上线、商业化收费、合规风控、长期迭代。  
> 版本：Final V1.0  
> 生成日期：2026-05-22  

---

## 0. 最终结论

本项目不能按传统 SaaS 的“市场分析 - PRD - 原型 - 技术方案”粗线条推进，也不能把文档做成过度完整但低研发价值的资料堆。

最优文档体系应该围绕一个核心目标：

> 让 AIcoding 执行团队可以在不反复追问、不频繁返工、不丢失上下文的情况下，把一个 AI 自媒体商业产品从概念推进到可上线、可收费、可风控、可持续迭代的工程系统。

因此，本项目最终需要 **24 份文档**。其中：

- **15 份为核心文档**：必须单独开 ChatGPT Project 深度展开。
- **9 份为重要支撑文档**：上线前必须有，但可以轻量化或与核心文档联动生成。

这不是为了追求“大而全”，而是因为本项目同时具备以下复杂度：

1. 它是 AI 产品，不是普通 CRUD SaaS。
2. 它涉及视频、多模态、Prompt、生成模型、任务队列、文件资产、成本控制。
3. 它涉及版权、肖像、AIGC 标识、内容审核、平台规则等合规风险。
4. 它要用 AIcoding 自动化研发，必须把上下文、边界、验收、接口、Schema、Prompt 事先固化。
5. 它的长期壁垒不是页面，而是 Content DNA、Creative IR、Prompt 体系、质量评测、风控、数据归因和提示词进化。

## 1. 对上一版回复的深度复盘与修正

上一版回复的主方向正确：

1. 没有简单照搬原方案里的所有文档，而是按商业级上线需要进行了压缩。
2. 正确强调了 Content DNA、Creative IR、Prompt、风控、数据库/API、任务队列是 AI 产品核心。
3. 正确把第一阶段从“视频复刻”收敛到“高质量拆解 + 原创脚本 + 可用 Prompt + 可验证付费”。
4. 正确把合规、安全、原创化重构作为底线。

但仍有 5 个需要补强的地方：

### 1.1 缺少“AI 评测样本集与 Benchmark 文档”

上一版提到质检，但没有单独设立“AI 输出评测样本集”。这是 AI 产品研发的关键缺口。

没有 Benchmark，会出现以下问题：

- Prompt 改了以后不知道质量有没有下降。
- 模型换了以后不知道输出是否稳定。
- 拆解报告看起来很好，但无法批量验证。
- AIcoding 做完功能后只能靠肉眼验收。
- 质检规则没有样本支撑，容易主观化。

所以本最终版新增：

> D12：AI 评测样本集、Benchmark 与回归测试文档。

### 1.2 缺少“AIcoding 执行规约文档”

上一版提到了 D00 总控文档，但没有把 Manus / Codex / Claude Code 的执行方式固化成独立文档。

本项目会大量依赖 AIcoding，如果不建立执行规约，会出现：

- Agent 自己决定技术方案，导致偏离产品文档。
- Agent 只做表面页面，不做后端真实逻辑。
- Agent 不写测试、不写迁移、不写日志。
- Agent 没有交接说明，后续账号或工具切换困难。
- 多个 Agent 并行开发时接口冲突。

所以本最终版新增：

> D23：AIcoding Agent 执行规约、提示词与交付标准文档。

### 1.3 数据安全与隐私不能只放进合规文档

上一版把隐私、授权、AIGC 标识放在合规文档里，但对工程研发来说还不够。

本项目会处理用户上传视频、账号信息、作品链接、生成视频、Prompt、用户业务信息、支付信息、发布数据等，必须单独定义：

- 数据分类分级。
- 权限模型。
- 数据留存周期。
- 文件访问权限。
- 删除机制。
- 敏感字段脱敏。
- 审计日志。
- 内部后台权限。

所以本最终版新增：

> D18：安全、隐私、数据治理与权限设计文档。

### 1.4 商业化上线不只是支付，还包括客服、退款、失败补偿、人工复核

上一版有商业化系统，但运营闭环不足。

AI 视频生成产品必然会出现：

- 生成失败。
- 用户不满意。
- 积分扣错。
- 用户投诉侵权。
- 内容被平台判搬运。
- 高风险内容需要人工审核。
- 企业用户需要客服和工单。

所以本最终版新增：

> D22：运营后台、客服、退款补偿与人工复核 SOP 文档。

### 1.5 缺少最终验收与交接文档

AIcoding 多任务研发非常容易出现“单模块完成，但整体不可交付”的问题。

因此需要最终交接文档，把项目从研发状态变成可运维、可继续迭代的资产。

所以本最终版新增：

> D24：最终验收、交接与后续迭代文档。

## 3. 推荐设计顺序

### 3.1 第一批：先确定产品与研发边界

这批文档决定项目方向，必须先做。

1. D00：AIcoding 项目总控文档 / 单一事实源
2. D01：产品战略定位与商业闭环文档
3. D02：首发用户画像、场景验证与行业选择文档
4. D03：MVP 范围定义与版本路线图文档
5. D04：总 PRD 文档
6. D05：功能模块拆分与独立研发边界文档

完成这 6 份后，项目才算具备“可被研发”的产品边界。

### 3.2 第二批：定义 AI 产品核心能力

这批文档决定产品质量与壁垒。

7. D07：Content DNA Schema 与拆解报告标准文档
8. D09：Creative IR Schema 与原创化重构规则文档
9. D10：Prompt 体系、变量、版本与测试文档
10. D12：AI 评测样本集、Benchmark 与回归测试文档
11. D13：质检评分、相似度风控与合规拦截文档
12. D08：视频处理与多模态理解工作流文档
13. D11：模型路由、供应商适配与成本控制文档

完成这 7 份后，AI 能力层才不会停留在“调用大模型生成一段文字”的水平。

### 3.3 第三批：定义工程系统硬契约

这批文档决定 AIcoding 能不能稳定开发。

14. D15：技术架构与工程模块设计文档
15. D16：数据库 Schema、数据字典与 API 契约文档
16. D17：异步任务队列、文件存储与资产生命周期文档
17. D18：安全、隐私、数据治理与权限设计文档
18. D06：用户流程、信息架构与页面原型说明文档

完成这 5 份后，可以进入较稳定的自动化研发阶段。

### 3.4 第四批：商业化、合规与上线

这批文档决定产品能否真实上线收费。

19. D19：商业化系统、套餐积分、订单与成本结算文档
20. D21：合规、授权、AIGC 标识与内容审核文档
21. D22：运营后台、客服、退款补偿与人工复核 SOP 文档
22. D20：测试、验收、发布、监控与告警文档

完成这 4 份后，产品才具备商业化上线条件。

### 3.5 第五批：AIcoding 执行与项目收口

23. D23：AIcoding Agent 执行规约、提示词与交付标准文档
24. D24：最终验收、交接与后续迭代文档

D23 实际上可以提前到第一批之后做，因为它会直接影响 Manus/Codex 的执行质量。

## D00：AIcoding 项目总控文档 / 单一事实源

### 级别

S+

### 设计目的

建立整个项目的“唯一真相来源”。所有 ChatGPT Project、Manus、Codex、Claude Code、研发人员都必须以此为根上下文。

### 必须解决的问题

1. 项目到底是什么。
2. 当前版本做什么。
3. 哪些功能不做。
4. 所有文档如何关联。
5. 所有模块如何拆分。
6. 每个 Agent 应该遵守什么规则。
7. 如何验收商业级交付。

### 必须包含

1. 项目一句话定位。
2. 产品长期愿景。
3. 当前 MVP 目标。
4. 首发用户与场景。
5. P0/P1/P2 功能边界。
6. 24 份文档目录。
7. 核心文档依赖关系。
8. 研发模块拆分总览。
9. AI 能力链路总览。
10. 数据链路总览。
11. 风控与合规底线。
12. AIcoding 执行原则。
13. 质量验收总标准。
14. 禁止事项。
15. 变更管理规则。

### 落地注意事项

- D00 要尽量短而硬，不要写成厚文档。
- 每次新建 Project，都要把 D00 作为第一份上下文。
- D00 中只写原则和索引，不展开细节。
- D00 每次大版本变化都要更新。

### 验收标准

- 新 Agent 只读 D00，就能理解项目方向和研发边界。
- D00 能指向所有关键文档。
- D00 明确禁止“复制搬运”“仿脸仿声”“未授权素材复用”等高风险方向。

## D01：产品战略定位与商业闭环文档

### 级别

S

### 设计目的

把产品从“对标账号复刻工具”升级为“AI 短视频爆款增长引擎”。

### 必须解决的问题

1. 产品为什么成立。
2. 用户为什么付费。
3. 长期壁垒是什么。
4. 产品不是做什么。
5. 第一阶段商业闭环是什么。

### 必须包含

1. 产品定位。
2. 一句话价值主张。
3. 目标用户。
4. 用户核心痛点。
5. 产品核心能力。
6. 第一版产品形态。
7. 第二版产品形态。
8. 第三版产品形态。
9. 收费逻辑。
10. 长期壁垒。
11. 不建议做的定位。
12. 合规表达口径。
13. 商业成功指标。
14. 护城河假设。
15. 可被验证的商业假设。

### 推荐核心判断

产品不应被定义为：

- AI 搬运工具。
- 爆款复制器。
- 对标账号克隆器。
- 视频洗稿工具。
- 自动搬运系统。

推荐定义为：

> 输入对标账号或爆款视频，系统自动拆解爆款规律，生成适合用户行业、人设、产品和素材的原创脚本、分镜、提示词与视频草稿，并根据发布数据持续优化内容策略。

### 落地注意事项

- 不要把商业战略写成融资 BP。
- 要写成能指导产品取舍的研发文档。
- 所有宣传语必须规避“1:1 复刻”“克隆”“搬运”等高风险表达。

## D02：首发用户画像、场景验证与行业选择文档

### 级别

A

### 设计目的

确定第一批产品服务对象，避免一开始做全行业。

5. 依赖仿脸仿声的账号。
6. 强医疗、金融、法律建议类内容。

### 必须包含

1. 首发行业选择理由。
2. 用户画像。
3. 用户真实痛点。
4. 用户现有工作流。
5. 用户愿意付费的交付物。
6. 用户上传材料。
7. 用户期望结果。
8. 用户购买触发点。
9. 冷启动验证方法。
10. 用户访谈问题。
11. 付费意愿测试。
12. 留存假设。
13. 不适合用户清单。
14. 样本视频收集标准。
15. 行业模板优先级。

### 落地注意事项

- 目标用户不能只写“自媒体人”，太宽泛。
- 第一版建议选一个细分行业做深，不要追求通用。
- 每个用户画像必须能映射到具体功能和交付物。

## D03：MVP 范围定义与版本路线图文档

### 级别

S+

### 设计目的

防止第一版功能过重，明确研发边界。

### 推荐版本路径

#### MVP 0：半自动服务验证

- 用户提交对标视频。
- 人工 + AI 输出拆解报告。
- 输出原创脚本和 Prompt。
- 验证用户是否愿意付费。

#### MVP 1：视频拆解 + 原创脚本生成

- 上传视频。
- 自动抽帧、ASR、OCR。
- 多模态拆解。
- 输出 Content DNA。
- 输出拆解报告。
- 输出原创脚本。
- 输出视频生成 Prompt。

#### MVP 2：对标账号分析 + 批量内容计划

- 添加对标账号。
- 作品列表导入。
- 爆款筛选。
- 栏目分析。
- 选题矩阵。
- 一周内容计划。

#### MVP 3：视频生成 + 拼接 + 质检

- 分镜 Prompt。
- 视频片段生成。
- 拼接。
- 字幕。
- 封面。
- 质检。
- 导出。

#### MVP 4：数据诊断 + Prompt 进化

- 发布数据导入。
- 单条视频诊断。
- 账号趋势分析。
- 归因报告。
- 下一条优化建议。
- 高表现 Prompt 沉淀。

### 第一版必须做

1. 用户登录。
2. 用户画像。
3. 视频上传。
4. 视频处理。
5. 多模态理解。

## D09：Creative IR Schema 与原创化重构规则文档

### 级别

S+

### 设计目的

建立模型无关的创意中间层，避免从视频拆解结果直接生成模型 Prompt。

### 为什么必须有 IR

不同视频生成模型能力不同，如果直接从拆解报告生成 Prompt，会导致：

- 模型切换成本高。
- Prompt 不稳定。
- 风控难插入。
- 版本难回溯。
- 成本难估算。
- 生成质量难评测。

推荐链路：

> Content DNA → Creative IR → 模型专用 Prompt → 视频生成 / 脚本生成 / 分镜生成

### 必须包含

1. Creative IR 总 Schema。
2. 用户画像字段映射。
3. Content DNA 字段映射。
4. 原创化策略。
5. 平台适配字段。
6. 人设适配字段。
7. 产品/服务植入字段。
8. 分镜字段。
9. 相似度控制字段。
10. 风险控制字段。
11. 版本管理字段。
12. 模型目标字段。
13. 从 Content DNA 到 IR 的转换规则。
14. 从 IR 到 Prompt 的转换规则。
15. 示例 JSON。
16. 验收标准。

### 原创化强度

1. 低强度结构参考。
2. 中强度行业改写。
3. 高强度原创重构。
4. 强原创裂变。

### 落地注意事项

- 默认输出应为“原创化重构”，不是“高度相似复刻”。
- D09 是连接 AI 理解与 AI 生成的核心文档。
- D09 必须与 D13 相似度风控联动。
